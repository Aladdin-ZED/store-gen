# r1-p6-9: `test:tenancy` publishes a lean copy of the argan baseline once the height model is real

- Status: open
- Filed by: P6 · Owner of the file: maintainer (core §K.3; `scripts/qa/tenancy-check.ts`)
- Files: `scripts/qa/tenancy-check.ts` (one block of `moreSpecialCases`), no code of another track
- Relates to: r1-p6-4 (the same premise in `test:prepublish`)

From P6 step 3 on, `estimateHeights` and `variantFeatures` are real, so the budget gate's hard rows refuse (§M.2,
`heightModelIsStub()` is false). In P6's worktree, `test:tenancy` has 5 failures, all in `[special cases]`, and all
come from that one cause:

```
✗ A publishes /argan (the real render)                        PublishError budget_blocked
✗ B publishes /argan (the same slug)                          PublishError budget_blocked
✗ B publishes a page whose document names A's files           PublishError budget_blocked
✗ render: /s/<A>/argan serves A's page (A's product name)     404 (nothing was published)
✗ render: /s/<B>/argan serves B's page (B's product name)     404
```

The suite seeds every page with the argan baseline fixture. On its own document, that fixture trips these hard rows
(probe `budgetReport({ doc })`, 2026-11-04):

```
budget:C3 {"count":25,"limit":16}     budget:C3 {"px":28683,"limit":15000}
budget:F1 {"px":13702,"limit":3000}   budget:C2 {"px":1017,"limit":844}
budget:R4 {"count":9,"limit":4}       budget:K2 {"count":6,"limit":4}
```

These rows are correct, and they are what the gate exists to refuse (see r1-p6-4). The failing cases test the
scoping of a publish, not the budget. They need a document the gate accepts.

## Why

`npm test` must stay green from the P6 merge on (core §J.1), and P6 cannot edit the file. Two other fixes were
possible, and both are worse:
- a model that under-reports the baseline, which would be dishonest;
- skipping the budget gate in the suite, which would mean the suite no longer publishes through the real path.

## Effect on others

None. The suite still exercises the real publish path, gates included. Until this CCR is applied, `test:tenancy` in
P6's worktree shows these 5 failures. P6's step reports list them as known, with this CCR.
