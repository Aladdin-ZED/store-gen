# r1-p5-1: export the AI guard's number scanner (`numbersIn`, `allowedNumbers`) from `src/lib/ai/guard.ts`

- Status: open
- Filed by: P5 · Owner of the file: P7 (`src/lib/ai/**`)
- Files: src/lib/ai/guard.ts

## What

Export the two existing functions unchanged (additive, no behaviour change):

```diff
-function numbersIn(s: string): string[] {
+export function numbersIn(s: string): string[] {
   return ASCII_DIGITS(s).match(/\d+(?:[.,]\d+)?/g)?.map((n) => n.replace(",", ".")) ?? [];
 }

 /** Numbers the copy may mention: those the merchant gave us (facts, name, price, delivery line). */
-function allowedNumbers(ctx: GuardContext): Set<string> {
+export function allowedNumbers(ctx: GuardContext): Set<string> {
```

Once applied, P5 replaces its local copy in `src/lib/integrations/templates.selftest.ts` (`numbersIn`,
`allowedFrom`, marked "guard.ts does not export … CCR r1-p5-1") with an import of `numbersIn` (and builds its allowed
set with `allowedNumbers({ locale, productName: "", facts })`), and drops the parity probe.

## Why

OPE-§O.1 (the templates paragraph of `test:conversions`) and OPE-§7.4's acceptance require the template self test to
prove "zero numbers not present in the order or settings" with **the number scanner of `src/lib/ai/guard.ts`
`allowedNumbers`, reused** (brief p5-01: "read-only import of allowedNumbers, src/lib/ai/guard.ts:52"). Neither
function is exported today, so the scanner cannot be imported. P4's `test:ops` (the built-in call script over the same
40 fixtures, OPE-§7.4) needs the same import.

Meanwhile P5 mirrors the two functions' rules (Arabic-Indic and Persian digits folded, `\d+([.,]\d+)?`, the comma
read as a decimal point, `n` and `String(Number(n))` both allowed) and proves the mirror equal to the guard on eleven
probes through the guard's exported `cleanAiText` (a probe passes the mirror if and only if `cleanAiText` keeps it).

## Effect on others

- None on frozen contracts. Two names become importable; no caller changes.
- P4 (`test:ops`) and P5 (`test:conversions`) import `numbersIn` / `allowedNumbers` read-only after the change.
