## 2. Orders stays T4's item

Core §I.3 lists Orders under Sell for P4, but `nav/t4.ts` already contributes `id: "orders"` and the registry spreads
both files, so a second item would draw Orders twice. P4 leaves it to t4.ts; nothing to apply unless the maintainer
moves the item, in which case it moves into `nav/ops.ts` unchanged (`order: 10`, badge `newOrders`).

## 3. The Profit item has no flag gate

`NavItem` carries no flag field, so the Profit item shows with `finance.read` whatever `finance_lite` says; the
`/finance` screen answers the flag itself. If the maintainer wants the sidebar to follow the flag, add
`flag?: FlagKey` to `NavItem` (`nav/types.ts`) and a `flagOn(flag)` test in `navItemVisible` (`nav/index.ts`); P4 then
sets `flag: "finance_lite"` on the item.

## 4. The board's pulse between polls (OPE-§14.1)

The board polls `/ops/state?view=board` every 15 s. The spec also wants it to read the shared pulse's `counts.*`
between its own polls; there is no client hook for the pulse in the shell today. When P2 exposes one (for example
`usePulse(): StorePulse | null` from the shell's poller), P4 merges `counts.toCallNow` / `callbacksDue` /
`firstTouchBreaches` into the tiles between polls; until then the tiles move every 15 s.
