# r1-p7-3: the wizard's AI merge passes guard v2's context, the kicker plan in PageCopy keys, and keeps the origin map

- Status: open
- Filed by: P7 · Owner of the file: P6
- Files: src/components/generate/wizard.tsx (the `mergeAiCopy` call, today line 614), src/components/generate/kit.ts
  (re-export only, unchanged)

## What

At the wizard's merge of AI copy over the library (`kit.mergeAiCopy(library, copyJob.copy, ctx)`), pass guard v2's
context and keep what it returns:

```ts
const merged = kit.mergeAiCopy(library, copyJob.copy, {
  locale: details.locale, productName: name, facts, price, deliveryText,
  // guard v2 (src/lib/ai/guard.ts GuardContext): any of these fields switches the v2 rules on
  origin: copyJob.provider === "server" ? "cloud" : "local",
  kickers: new Set(kickerSectionsOf(compiled.copy)),   // design's CopyDirectives.kickers, as PageCopy section keys (below)
  hasWhatsapp: Boolean(store.whatsapp),
  wordsAvoid: storeAi.voice.wordsAvoid,                // when the wizard has the store's AI settings
  policies,                                            // when the wizard has the store's policies; absent = rule 3 off
  freeShipping,                                        // the page's real fee is 0 or the offer has free shipping
});
// merged.origin: Record<"hero.headline" | "faq.items.0.q" | …, "cloud" | "local" | "library"> → the draft's
// generation record (design_genomes.report.gen, the `o` of each recorded path), mapped from PageCopy paths to doc paths
```

- **The kicker plan's keys.** `GuardContext.kickers` names PageCopy sections: `KICKER_SECTIONS` in
  `src/lib/ai/copy-schema.ts` (`benefits`, `problem`, `showcase`, `steps`, `story`, `reviews`, `socialProof`, `gallery`,
  `specs`, `offer`, `guarantee`, `form`, `cta`, `faq`). The wizard maps design's per-section `kicker: true` (G32, DES-§5.8)
  to these keys (the section's copy-map key, the way `src/lib/generator/copy-map.ts` reads `c.<key>.kicker`). A section
  outside the set loses its kicker, library or model; the hero keeps its own (DES-§5.8 V30 repair "the hero keeps its
  own", AI-§D.2 rule 11).
- **A server value is partial.** `copy.page`'s finalize returns the guarded keys only (`Partial<AiCopy>`); `mergeAiCopy`
  reads any object key by key and keeps the library for the keys it lacks, so the wizard passes the server value as is.

## Why

- DES-R20 (core §K.2 P7 row, accepted): "`mergeAiCopy(library, ai, ctx)` gains `ctx.kickers` … P6's wizard passes the
  set".
- AI-§D.2 rule 13 / QUAL-1: `mergeAiCopy` v2 returns `origin: Record<fieldPath, CopyOrigin>` so the draft's generation
  record tells a `cloud` line from a `library` one at publish (`originFrom`).
- P7 step 2 keeps every existing caller's behaviour when the new fields are absent (the brief's rule), so guard v2's new
  rules (number words, claim nouns, policies and call timing, links, dashes and middle dots, the Darija guide) run only
  in a v2 context (`isGuardV2(ctx)`: any v2 field set; the server's `finalizeCtxFor` sets them all). Until the wizard
  passes them, local copy merged in the browser is judged by the R1.0 rules; server copy is already judged by v2 on the
  server.

## Effect on others

- `src/lib/generator/selftest.ts` (P6) calls `mergeAiCopy` with an R1.0 context and keeps passing unchanged (its steps
  fixture, "Trois gouttes" / "Une minute suffit.", would be refused by rule 5's number words in a v2 context; if P6
  moves that check to a v2 context, those two lines change too).
- No frozen contract changes; `MergeResult` only gains `origin`.
