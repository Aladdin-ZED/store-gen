## 3. Self-review of the diff (`git diff 5bbef59`)

- **Scoping.** Every store-table query in T1's files uses `whereStore` / `storeValues` or `store_id = ?` with the
  scope's id: `store_settings`, `store_entitlements`, `signup_reviews`, `store_usage`, `audit_log` (tenant listing),
  `media_files` / `pages` / `store_members` (gauges), and the conversion over store #1. The unscoped reads are platform
  rows by design, each marked `// tenancy: platform`:
  - `stores` by id;
  - handle availability across stores, with no oracle;
  - `flags`, `protected_brands`, `cron_cursors`, `platform_usage`;
  - the `forEachStore` iterator.
- **Caches.** Every process cache is keyed by store: settings use (storeId, key), with platform rows under `"p"`;
  entitlements use (storeId, "all"). A ULID store id can never equal `"p"`. Kill switches and handle lists are
  platform caches, and derived keys are keyed by the full info string, which includes the store. `invalidateStore`
  drops the settings and entitlement entries through the cache registry.
- **Secrets.**
  - No log line carries a value. Settings log the key and the reason, never `JSON.parse` messages, which would quote
    the decrypted text. The conversion names only the key that fails to open, and the boot config lines print names
    and states.
  - `test:migrate` uses a random APP_SECRET per run and `example.test` data.
  - No `.env*` file was read or printed.
- **Contract drift vs §D / §E.** Every frozen C0a signature keeps its shape. The only changes are additive: optional
  `opts` defaults, plus `limit` / `area` on the audit listings, and a `kind` field on `SettingsActor` /
  `PlatformActor`. No schema or migration file was touched (the DDL needs are CCRs). PageDoc v2, runtime config v2,
  payload v2, the PHP export and the landing chunk are untouched.

## 5. Deviations and decisions

- **Legal seed (§H.4 step 5) not run.** Its data file and marker key are not in any R1.0 row (CCR 3 item 1). Boot step 5
  adds it once the maintainer creates them.
- **`syncPromptVersions()` (§H.4 step 5) not run.** `src/lib/ai/platform/prompt-versions.ts` and `prompt_versions` do
  not exist in R1.0; they belong to P7 in R1 product. Whoever cuts them adds one `step(...)` line in `runBootTasks`
  (`src/lib/db/boot-tasks.ts`, T1's in R1.0).
- **Boot step 3 (the media storage check) is empty.** It has nothing to check until the filesystem backend arrives
  (§G.2).
- **Handle re-check (§D.8 step 3).** The protected brands are seeded at boot, after 0004 derived the handle. A derived
  handle that fails the re-check becomes `store-1`; if `store-1` is taken it is left as it is and logged, and the owner
  uses the free rename.
- **Pixel migration port.** `pixel_health` is now written before `tracking_secrets`. With the old order, a run
  interrupted between the two never wrote health for the copied ids, and `test:migrate` (d) catches it (CCR 3 item 3).
- **`forEachStore` cursor.** It is kept in process memory until `cron_cursors` (0005) exists, and the first write after
  0005 moves it to the table.
