## What

1. **src/lib/security/burst-limit.ts** (no R1.0 owner, C0a drift item 8). Add the auth forms to `BURST_LIMITS`, so
   `publicAction` gets its in-memory floor before any DB work (§B.2 step 1, §B.1):

   ```ts
   /** public auth forms: the DB buckets keep 5/h (signup, report) and 10/15 min (invite, reset, login per IP) */
   signup: { limit: 20, windowSec: 600 },
   invite: { limit: 30, windowSec: 600 },
   reset: { limit: 30, windowSec: 600 },
   report: { limit: 20, windowSec: 600 },
   login: { limit: 60, windowSec: 600 },
   ```

   Nothing else changes: `publicAction` (src/lib/auth/public-action.ts) already calls `burstLimit(name, ip)` for every
   name that is a key of `BURST_LIMITS` (`Object.hasOwn`), and `BurstName` = `BurstScope | "signup" | "invite" |
   "reset" | "report" | "login"`, which collapses to `BurstScope` once the names exist.

2. **scripts/qa/tenancy-allow.json** (C0b, lint L4). One entry beside the ones C0a listed:

   ```json
   { "file": "src/lib/auth/password.ts", "symbol": "__sgScrypt", "reason": "the scrypt semaphore (§B.3): one process-wide gate, no tenant data" }
   ```

   The mail dedupe and cap counters use `scopedCache` (store id "p"), so they need no entry.

3. **§H.7 and .env.example**: the optional R1 mail transport (src/lib/mail/index.ts, §B.10):

   ```
   SMTP_URL=      # optional: smtps://<user>:<password>@smtp.hostinger.com:465 (or smtp://…:587 with STARTTLS). Unset = mail off
   MAIL_FROM=     # with SMTP_URL: "Store Gen <no-reply@your-domain>"
   ```

   Both unset (the default) keep R1's documented behaviour, `mailer().enabled === false`. A pair that does not parse
   is logged once (never its values) and mail stays off.

## Why

(1) §B.2 step 1 and §B.1 ("Forms are server actions wrapped in publicAction: Turnstile check, burst limit, DB buckets")
need an in-memory window per form; the file has no owner in R1.0. (2) L4 fails on any module-scope `globalThis.__sg*`
not in the allow file; the semaphore must be process-wide because the RSC and route-handler layers may load
`password.ts` twice. (3) A deploy needs the variable names written where the owner looks for them.

## Effect on others

None on frozen contracts. Until (1) lands the auth forms run on their DB buckets alone (`p:signup:ip` 5/h, …).
