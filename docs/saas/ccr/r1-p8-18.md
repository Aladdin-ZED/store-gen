Replace it with a real case over P8's `replay` and `outboxSummary` (both in `src/lib/jobs/outbox.ts`), run through

```ts
// a store-side replay(ctx, id) of another store's outbox row → not_found, A's row unchanged (§F.1 rev 2.1, OPE-§28.3)
{
  const { pool } = load<typeof import("@/lib/db/client")>("@/lib/db/client");
  const { newId } = load<typeof import("@/lib/db/ids")>("@/lib/db/ids");
  const O = load<typeof import("@/lib/jobs/outbox")>("@/lib/jobs/outbox");
  const S = load<typeof import("@/lib/tenancy/seam")>("@/lib/tenancy/seam");
  const deadA = newId();
  await pool().query(
    "INSERT INTO outbox (id, store_id, kind, topic, dedupe_key, payload, state, attempts, last_error) VALUES (?, ?, 'telegram', 'new_order', ?, ?, 'dead', 7, 'Forbidden')",
    [deadA, fx.A.id, `tenancy:${deadA}`, JSON.stringify({ phone: fx.canary.phone })],
  );
  const snapA = await snapshot(fx.A.id);
  for (const role of ["owner", "admin"] as const) {
    // the roles holding integrations.manage reach replay; the others are refused by the P5 action's permission first
    const r = await call({ userId: fx.B.members[role] }, appPath(fx.B.handle, "/integrations"), async () => O.replay(await S.requireStoreMember(), deadA));
    check(`replay as B's ${role} with A's outbox id → not_found`, r.kind === "threw" && (r.error as { code?: string }).code === "not_found", r);
    const sum = await call({ userId: fx.B.members[role] }, appPath(fx.B.handle, "/integrations"), async () => O.outboxSummary((await S.requireStoreMember()).scope));
    check(`outboxSummary as B's ${role}: no row of A, no canary`, sum.kind === "ok" && !JSON.stringify(sum.value).includes(deadA) && leaks(sum.value).length === 0, sum);
  }
  check("replay from B: A's rows unchanged", (await snapshot(fx.A.id)).hash === snapA.hash, snapshotDiff(snapA, await snapshot(fx.A.id)));
}
```

The `Outcome` field names (`kind`, `error`, `value`) and the canary fixture name are the harness's; adapt them to its
helpers as written at the merge. When P5's `replayDeliveryAction` lands, its own action case (P5's
`tenancy-cases/integrations.ts`, `actions`) covers the action path and the role matrix; this case keeps the library
path, which the console's `replayOutboxAction` (P1) also reaches.

`snapshot()` must include the `outbox` table (it is a tenant table since 0005; the harness's snapshot lists the
store's tables from the schema, so it should already; check at the merge).

## Why

§F.1 lists the case by name and the R1.0 harness marked it "not applicable" until P8. P8 has no case file of its own
(§K.2 gives P8 no `tenancy-cases/<track>.ts`), and P8's own DB suite already proves the rule on the library
(`test:storage`, section `outbox`: B's scope on A's row → `not_found` and A's row byte-identical; the impersonation
refusal; `outboxSummary(B)` names no row of A and holds no payload canary). This CCR moves the same proof into the
two-store attack suite, where §F.1 and OPE-§28.3 (3) / (4) want it.
