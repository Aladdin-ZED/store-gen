## What

1. **src/instrumentation.ts.** §E.4: "boot logs an error and ignores it otherwise". Call the T2 helper once at boot,
   before the other tasks (it never throws, it only logs):

   ```ts
   import { identityContextMisconfigured } from "@/lib/tenancy/context";

   ```

   it visible at start-up rather than at the first request.

2. **`activeKillSwitches()`** (src/lib/tenancy/entitlements.ts). The seam reads `platform_read_only` (§H.8) through it
   on every store and platform write (`platformReadOnly()` in src/lib/tenancy/seam.ts). Please keep:
   - the 30 s `scopedCache("flags")` cache (§E.6), since the call sits on the write path of every action;
   - a read error **thrown**, never answered as "no switch", so a write is never let through on a failed read;
   - the stub's message prefix `not implemented: T1` until the body lands: the seam treats exactly that error as
     "no switch tripped" (the 0004 default), and every other error as a refusal.

## Why

(1) is the letter of §E.4. (2) is what the seam's read-only guard assumes, so it fails closed after T1 merges.
