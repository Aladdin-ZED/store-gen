## 1. The `page.publish.design_override` audit (maintainer, `publish.server.ts`)

`publishPage` passes `mode: "block"` to `runPrePublishChecks` and never reads the flag `design_publish_gates` or
`platform_design.gatesAtPublish`. The design check therefore computes its own effective mode (`designGateMode`: the core's
`warn` wins, else the flag and the setting, the weaker of the two). In warn mode it answers `{ ok: true, notes }` where
the items that would have refused keep `level: "hard"` (DES-§8.8's `return { ok: true, notes: [...items, ...notes] }`).
Nothing audits that override today. Proposed, right after the gate in `publishPage` (both call sites, 430 and 746):

```diff
   const gate = await runPrePublishChecks(gateCtx);
   if (!gate.ok) throw new PublishError(gate.code, GATE_MESSAGES[gate.code], [], undefined, gate.items);
+  const overridden = gate.notes.filter((n) => n.level === "hard");
+  if (overridden.some((n) => n.id.startsWith("design:")))
+    await audit("page.publish.design_override", { userId: actor.userId, ip: actor.ip, target: page.id, scope: auditScope(scope, actor), meta: { items: overridden.filter((n) => n.id.startsWith("design:")).map((n) => n.id).slice(0, 20) } });
+  if (overridden.some((n) => n.id.startsWith("budget:")))
+    await audit("page.publish.budget_override", { userId: actor.userId, ip: actor.ip, target: page.id, scope: auditScope(scope, actor), meta: { items: overridden.filter((n) => n.id.startsWith("budget:")).map((n) => n.id).slice(0, 20) } });
```

`runPrePublishChecks`' own warn branch (re-renders) maps refusals to `level: "soft"`; it may keep `level` instead so the
same audit line covers it. FL-1's proof stays the maintainer's `test:prepublish` / `qa:publish-gates` at the merge.

## 2. The listener's `error_events` row (P8, `recordError`)

DES-§8.8 rule 3: a listener failure is an `error_events` row with area `design`. `recordError` (§H.5) is not in the tree
(P8). Until then `designListener` logs `[design] publish listener (<event>) failed: <errorSummary>` and returns. At the P8
merge, in `src/lib/render/prepublish/design.ts` (P6 file, the maintainer may apply it):

```diff
   } catch (err) {
-    console.error(`[design] publish listener (${ctx.event}) failed:`, errorSummary(err));
+    recordError({ area: "design", code: `listener_${ctx.event}`, storeId: ctx.scope.storeId, err });
   }
```

## 3. The brand facts of `design:brand_empty` (P1, the health job)

`design:brand_empty` needs the logo and the colour locks. `HealthInputs.brand` (frozen) has no such fields, so the
rule reads the store's own `brand` setting through the scope. Proposed for P1's job: fill `inputs.brand` with two more
fields, `logo: boolean` (any of `logo.primary / mark / wordmark`) and `colorLocked: boolean` (`colors.locks.length > 0`);
the rule already prefers them when present (its `test:health` fixture passes them), so the extra read disappears without
a P6 change.
