# r1.0-t4-11: the moved dashboard's calls into the render path and the proxy

- Status: open
- Filed by: T4 · Owner of the files: T3
- Files: src/lib/render/publish.server.ts, src/lib/render/cache.server.ts, src/proxy.ts

## What

1. `publishPage(scope, pageId, { actor, expectedUpdatedAt? })` (C0a's frozen scoped overload) is now the only form the
   dashboard calls: the pages list (`/app/<h>/pages`), the builder's Publish and the builder's slug move of a live
   page (`src/lib/editor/actions.ts`, re-publish then `revertSlug(scope, …)` on failure). Until it is implemented it
   throws "not implemented: T3", which the actions answer as "server" (logged) / "Something went wrong".
2. `publishTrackingOnly`: the pixels actions (`src/lib/pixels/actions.ts`, T4: "Update live page now", Replace on
   live pages) still call the store-less `publishTrackingOnly(pageId, userId, tracking, baseVersionId, opts)` after
   reading the page in the scope's store. A scoped overload to switch to:

   ```ts
   export function publishTrackingOnly(scope: WriteScope, pageId: string, tracking: Tracking, baseVersionId: string, opts: { actor: Actor; patchDraft?: boolean }): Promise<TrackingOnlyResult>;
   ```

   (looked up with the store predicate, audited in the store; CCR r1.0-t4-2's `enforceLibraryRule(scope, …)` inside).
3. `invalidatePublished()` (cache.server.ts): the dashboard calls it after a store's identity, Turnstile keys or a
   slug change (`src/app/app/[store]/settings/actions.ts`, `src/lib/admin-data/store-profile.ts`,
   `src/lib/editor/pages.server.ts`). A per-store form (`invalidatePublished(storeId)` or `invalidateStore(storeId)`
   registered for the render cache, §E.6) lets T4 drop the platform-wide clear.
4. `src/proxy.ts`: `/app/**` (HTML, the `app` area) needs the per-request nonce CSP and the nonce request header like
   `/admin/**` today: the dashboard layout reads `getCspNonce()` for the theme script, and the draft preview route
   `GET /app/<h>/preview/<id>` serves landing HTML whose inline scripts get that nonce. Without a nonce the preview
   still renders (no CSP header is set on that path today), but under T3's area CSP its scripts need it.

## Why

§E.2, §I.1, §H (render). The dashboard move (T4 step 4) routes every publish through the store's scope; (1) and (2)
are the render side of the same calls, (3) PUB-* per-store invalidation, (4) §C.3 / §F.6 headers for the new area.

## Effect on others

- None on frozen contracts.
- `scripts/qa/pixels-publish-check.ts` (T4) runs its publish block once (1) answers.
