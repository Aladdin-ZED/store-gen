# r1-p7-10: the `ai` area of `DATA_AREAS` and `dataPath` for job blobs

- Status: open
- Filed by: P7 (step 8) · Owners: P8 (src/lib/storage/paths.ts, core §G.7), maintainer (the extension point)
- Files: src/lib/ai/jobs/blob.ts (P7, at the merge)

## What

Core §G.7 builds every `DATA_DIR` path with `dataPath(area, storeId?, …)` from src/lib/storage/paths.ts, and the purge
and the export iterate `DATA_AREAS`, where `ai: { perStore: true }` is a row (AI-§B.13 step 7, AI-§R.1 "the ai row of
the DATA_AREAS registry through its extension point"). Neither file exists in the P7 base: they are P8's.

Step 8 writes stage outputs over 64 KB to `DATA_DIR/ai/<storeId>/<jobId>/<stage>.json` through its own helper
(src/lib/ai/jobs/blob.ts), with §G.7's rules: both ids must be 26-character Crockford ids, the stage matches
`^[a-z]+(:[0-9]{1,2})?$`, no `..`, no absolute segment; without `DATA_DIR` the output stays in the row. `ai.retention`
deletes a job's folder with the job (30 days).

At the merge:

1. P8's `DATA_AREAS` gains (or already has) `ai: { perStore: true }`, so the store purge deletes `DATA_DIR/ai/<storeId>/`
   and `test:storage` covers it.
2. P7 replaces the path building in `aiBlobPath` / `removeJobBlobs` with `dataPath("ai", storeId, jobId, file)`
   (one change, same layout).

## Why

One path builder and one registry is what makes a purge complete (SEC-21); a private helper is only a bridge.
