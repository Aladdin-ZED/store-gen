# r1-p7-8: the `src/lib/ai/platform/**` pin of the tenancy lint

- Status: open
- Filed by: P7 (step 8) · Owners: maintainer (scripts/qa/tenancy-allow.json, core §F.1)
- Files: scripts/qa/tenancy-allow.json (maintainer)

## What

The allow file pins `src/lib/ai/platform/**` at `max: 0` ("counted at the P7 merge (§F.1); 0 before it", P0b CCR P7-7).
Step 8 adds the cross-store statements the collector, the sweeps and the rollups need, each annotated
`// tenancy: platform <reason>` in that folder and nowhere else, so the lint reports them as rule PIN until the pin is
raised. Count at step 8: **25 queries** (the lint's own pin count at the merge is authoritative):

| File | Queries | What |
|---|---|---|
| src/lib/ai/platform/batches.ts | 15 | the Batches queue: platform eval items (store NULL), the dedupe lookup, per-model counts, the next batch of one model (items of many stores), submit / unsubmit, the ingest's read and compare-and-set by item id, items left, job stages in flight, the eval run's items, unbuilt items, per-store counts of a batch, retention |
| src/lib/ai/platform/jobs.ts | 3 | the slot-4c sweep's candidates, terminal jobs with an open reservation, retention: ids and store ids only, each row then written through its own store's system scope |
| src/lib/ai/platform/rollups.ts | 3 | online counts per prompt version (the canary rules), the family's 7-day volume (the canary slice), the hour's quality counts per task (the AI-§O alarms): counts only |
| src/lib/ai/platform/maintenance.ts | 4 | abandoned running runs (ids, then finished through the store's scope), expired `ai_cache`, `ai_runs.output` after 90 days, `ai_runs` after 180 days |

`prompt-versions.ts` and `eval-runs.ts` touch only P tables (0 in the pin).

Proposed `scripts/qa/tenancy-allow.json` row:

```json
{ "files": ["src/lib/ai/platform/**"], "max": 25, "reason": "P7 merge (CCR r1-p7-8): the Batches collector (15), the job sweeps' ids (3), the canary and alarm counts (3), ai.reconcile and ai.retention (4); every per-store write goes through a system scope" }
```

## Why

A Message Batch mixes items of many stores (one model per batch, AI-§B.8), the slot-4c sweep must find orphans across
stores within 1 s (AI-§B.13 step 4) and the canary rollback compares a prompt version's runs across stores (AI-§F.8):
these are platform reads by nature. They are confined to the one folder D64 allows, they read ids, counts and the
items' own rows, and no write here spans stores except the queue's own item rows and retention deletes.
