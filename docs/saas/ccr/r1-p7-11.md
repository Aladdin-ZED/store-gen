# r1-p7-11: the tenancy route sweep's own-store records for `ai/jobs/[id]` and `ai/runs/[id]`

- Status: open
- Filed by: P7 (step 9) · Owner: maintainer (scripts/qa/tenancy-check.ts, core §K.3)
- Files: scripts/qa/tenancy-check.ts (`ownRoutePlan`)

## What

The generic route sweep of `test:tenancy` checks that a granted role of B "reaches the handler" on B's own store with
B's own records (`ownRoutePlan`); a route it has no record for gets `idFor(...)`, which is B's live page id for any
`[id]` segment it does not know. The two read routes of step 9 answer the neutral 404 of a missing id for an id that
is not one of the store's runs or jobs, by design (another store's id and a missing id answer the same bytes, AI-§A.7),
so with a page id the positive control fails six times:

```
✗ [routes] GET /api/app/[store]/ai/jobs/[id] · B owner|admin|editor · own store: reaches the handler with ai.use · 404
✗ [routes] GET /api/app/[store]/ai/runs/[id] · B owner|admin|editor · own store: reaches the handler with ai.use · 404
```

The attack halves of the sweep pass (A's handle: the unknown-handle 404; B's handle with A's ids: the missing-id
answer), and `scripts/qa/tenancy-cases/ai.ts` already proves the same routes with real runs, buffers and jobs of A
and B (both directions, the positive control included).

Requested change: give the sweep one run and one job of B for these two routes, read-only:

```ts
// in ownRoutePlan, before the `plans` table
if (key === "GET /api/app/[store]/ai/runs/[id]") return { ids: { id: await fresh.aiRunOf(B) }, plan: { query: { after: "-1" } } };
if (key === "GET /api/app/[store]/ai/jobs/[id]") return { ids: { id: await fresh.aiJobOf(B) }, plan: { query: { advance: "0" } } };

// in the Fresh helpers (the throwaway rows of B the sweep may create)
async aiRunOf(store) {   // a finished ai_runs row of the store, no customer column
  const { insertRun } = load<typeof import("@/lib/ai/store/runs")>("@/lib/ai/store/runs");
  return insertRun(scopeOf(store.id) as WriteScope, { userId: store.members.owner, task: "copy.hero", provider: "server", via: "interactive",
    inputHash: sha256Hex(`sweep-${store.id}`), finished: { status: "ok", ms: 1, credits: 0, costMicros: 0, output: { headline: "sweep" } } });
},
async aiJobOf(store) {   // a queued probe job of the store (sleep stages, no model, no credit), read with advance=0
  const { insertJob } = load<typeof import("@/lib/ai/store/jobs")>("@/lib/ai/store/jobs");
  const { probePlan } = load<typeof import("@/lib/ai/jobs/stages")>("@/lib/ai/jobs/stages");
  const plan = probePlan(2_000, 1_000);
  const id = newId();
  await insertJob(scopeOf(store.id) as WriteScope, { id, kind: "probe", task: "probe.sleep", inputHash: sha256Hex(`sweep-job|${id}`),
    progress: { done: 0, total: plan.stages.length, stages: {}, plan: plan.stages.map((s) => s.id) }, class: "director_deep",
    doc: { runIds: [], input: { totalMs: 2_000, stageMs: 1_000 }, plan: [...plan.stages], reservation: null },
    reservedCredits: 0, createdBy: store.members.owner, now: new Date() });
  return id;
},
```

(The same shape `scripts/qa/tenancy-cases/ai.ts` uses for A's records, `probeJobOf` and `insertRun`.) `advance=0` keeps
the positive control read-only, so it never runs a stage inside the sweep.

## Why

Without B's own records the sweep cannot tell a correct missing-id 404 from a broken route, and `test:tenancy` stays
red on these six lines until the merge. Nothing in the AI code changes.
