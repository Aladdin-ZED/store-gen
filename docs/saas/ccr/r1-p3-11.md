## What

1. `store-nav.ts` `ICONS` maps the four icon names P3's nav file uses: `Inbox` (Leads), `Truck` (Delivery zones),
   `PhoneCall` (After the order), `ScrollText` (Policies). Until then they draw the fallback circle.

   ```diff
   +  Inbox: InboxIcon,
   +  Truck: TruckIcon,
   +  PhoneCall: PhoneCallIcon,
   +  ScrollText: ScrollTextIcon,
   ```

2. The settings sub-navigation lists the registry's `settings` group (P2-08's plan): P3 contributes
   `settings-delivery`, `settings-checkout` and `settings-policies` (src/components/admin/shell/nav/landing.ts, order
   40-42, permission `settings.read`). Today `SETTINGS_NAV` is a fixed list, so the three tabs show in the sidebar's
   Settings group and not in the settings column. Descriptions for the tabs (en): "Zones, cities and the delivery
   calendar", "Thank-you page, calling hours and the order form", "Returns, delivery and what you promise".

3. `SeamErrorCode` gains `"brand_protected"` (core §E.2, D76: "the limit-sheet variant"), so a refused brand term
   answers `{ ok: false, error: "brand_protected" }` and P2's limit sheet opens. Until then `savePoliciesAction`
   answers `{ ok: true, data: { status: "brand_protected", field } }`, writes nothing, audits
   `store.brand_term.refused` and the policies screen shows the refusal inline on the field. P3 switches to the code in
   its next step after the merge.

4. LAN-§8.5: saving the store contacts (`saveStoreAction`, Settings → Store & legal) changes the thank-you and legal
   facts, so it also queues the live pages for a `store_info` re-render:

   ```diff

        refreshSettings(ctx.store.handle);
   ```

lists the store contacts among the saves that re-render the thank-you page.
