# r1-p5-10: build the creation event of a risky order, so trigger `confirmed` keeps its client data

- Status: open (optional; P5 codes against today's rule and `test:public-api` stays green)
- Owner of the change: the maintainer (`scripts/qa/public-api-security.ts` has no R1 owner) and P5
  (`src/lib/orders/conversions-core.ts`, one line)

## What

1. `purchaseConversion` (P5) drops its risk gate (`if (input.riskScore >= CONVERSION_MAX_RISK) return null;`): the event
   of a risky order is built and carries `risk`, and `planConversionEvents` alone applies the gate (trigger `order` at
   creation only, OD19). Nothing is sent at creation for a risky order either way.
2. `scripts/qa/public-api-security.ts`, check "connected export cannot skip an enabled Turnstile (the store's keys)":

```diff
-    assert.equal(browser.conversion, undefined, "no server-side Purchase for an unprotected order");
+    // the event is built (its client data is sealed for a later trigger), but nothing is sent at creation (OD19)
+    assert.ok(!browser.conversion || browser.conversion.risk! >= CONVERSION_MAX_RISK, "no creation Purchase for an unprotected order");
```

## Why

OD19: with trigger `confirmed` or `delivered`, the Purchase goes out at the agent's confirmation at any risk. Today a
risky order has no creation event, so nothing is sealed into `orders.capi_ctx`, and its confirmation sends the server
fields only (no IP, user agent, fbp, fbc, ttclid, ttp): a lower match quality for exactly the orders an agent rescued.

## Meanwhile

Step 6 keeps the R1.0 rule (no event for a risky order at creation). The confirmation path rebuilds from the order's
version (`ctx: "missing"` in the payload, `server_fields_only` in the timeline meta), so OD19 holds.
