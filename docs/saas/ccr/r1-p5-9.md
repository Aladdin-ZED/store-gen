# r1-p5-9: the outbox drainer cancels a dropped item (`cancelled:` error prefix) instead of marking it dead

- Status: open (P8 applies it in `drainOutbox`; P5 codes against today's `SendResult`, no type change)
- Owner of the change: P8 PLATFORM OPS (`src/lib/jobs/outbox.ts`)
- Asked by: P5 INTEGRATIONS, step 6 (`src/lib/jobs/handlers/capi.ts`)

## What

`drainOutbox` maps a final failure whose `error` starts with `cancelled:` to the row state `cancelled` (the state
already exists in `outbox.state`), with `last_error` = the text after the prefix and `done_at` set. Such a row is not
`dead`: it is not counted in `DrainReport.dead`, not listed by `outboxSummary(…).dead`, and `replay` refuses it like a
`done` capi row.

```ts
// src/lib/jobs/outbox.ts (P8)
/** A handler drops an item on purpose (the CAPI 7-day guard): a final failure with this error prefix → `cancelled`. */
export const OUTBOX_CANCELLED_PREFIX = "cancelled:";

// inside drainOutbox, where a failed send is recorded
if (!result.ok && !result.retry && result.error.startsWith(OUTBOX_CANCELLED_PREFIX)) {
  // UPDATE outbox SET state = 'cancelled', last_error = <rest>, last_status = <status>, done_at = now, claim = NULL,
  //   lease_until = NULL WHERE id = ? AND claim = ?
  report.done++; // or a new `cancelled` counter; never `dead`
  continue;
}
```

## Why

Core §H.1 and OPE-§20.4 (4) (OD20): the `capi` handler drops any ad event whose `event_time` is older than 7 days minus
1 hour at send time, records `capi_stale` on the order, and the item ends `cancelled`. `SendResult` has no cancel
variant, and adding one would change a frozen type (`src/lib/contracts/r1-p0.ts` P8Outbox). The prefix keeps the
contract as it is: the handler answers `{ ok: false, retry: false, error: "cancelled:stale_event" }`.

## Meanwhile

Until P8 reads the prefix, the stale item goes `dead` with the error `cancelled:stale_event`. The handler never fires
`int.delivery_dead` for it (it is not a delivery failure), and a replay of it is dropped again by the same guard, so the
only cost is one extra row in the dead list. `src/lib/jobs/handlers/capi.ts` exports the prefix as `CANCELLED_PREFIX`;
P8 may export its own constant and P5 switches to it at the merge.

## Tests

`test:integrations-db` (P5) asserts the handler's answer for a stale item (`cancelled:stale_event`, no fetch, the
`capi_stale` timeline event). P8's drainer test adds: a final `cancelled:` failure leaves the row `cancelled`, not
`dead`, and `replay` refuses it.
