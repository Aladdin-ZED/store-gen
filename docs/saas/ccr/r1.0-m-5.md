### 2. R2 contract step: a brand a spread cannot copy

Today's brand is `readonly [SCOPE]: true` with `declare const SCOPE: unique symbol`: TypeScript copies it through an
object spread, so `{ ...scope, storeId: id }` type-checks as a StoreScope. The lint closes that statically (L6), but
the type should carry it. Proposal: `StoreScope` becomes a class with an ECMAScript private field, constructed only
in `seam.ts`:

```ts
export class StoreScope {
  readonly #brand = true; // a spread or Object.assign does not copy a #private field: the result is not a StoreScope
  private constructor(readonly storeId: string, readonly kind: ScopeKind) {}
  /** @internal seam.ts only */ static mint(kind: ScopeKind, storeId: string): StoreScope { … }
}
```

`WriteScope` stays `StoreScope & { kind: "member" | "public" | "system" }` (the kind narrows; `#brand` still blocks a
spread). `storeIdOf()` in `sql.ts` adds `scope instanceof StoreScope` as its runtime check. Frozen-contract effect:
every `mintScope` caller (the four seam files), the selftests that fake a scope (they call a test-only minter), and
the JSON boundary (a scope is never serialized today; it stays so).

### 3. L4: plain-object caches (a spec gap, not a lint bug)

§F.1 words L4 as "`new Map(` / `new Set(`". A module-scope plain-object cache (`const C: Record<string, X> = {}`
written from request code) is the same process state with another syntax. Proposal for the spec owner: extend L4 to a
module-scope `const` / `let` object or array literal that a function writes to (`C[k] = …`, `C.push(…)`), with the
same `frozen` and allow-file exemptions. Not applied at R1.0: it widens the rule beyond its words and every track's
open files would gain hits mid-build.

## Why

The C0b review found that each rule had a bypass that type-checks and passes the lint (findings F1-F16, all fixed in
the lint with a `//!` fixture each). §F.1 is the contract the tracks read; it should say what the gate enforces. The
brand change makes the blocker (F1) a compile-time fact instead of a lint-time one.
