# r1.0-m-3: T2 actions and the §F.1 tenancy lint (L7, L9)

- Status: applied (L7 in "R1.0: T2 AUTH review fixes"; L9 in 54de35c, the C0b merge). Every T2 action starts with
  `return userAction(` / `publicAction(`; the forms read the result through `formStateOf()` (seam refusals → the same
  message keys as before, the non-secret fields kept). Six actions are in the allow file's new `actions` list (lint
  L9): `logout`, `setLocaleAction`, `setupAction`, `setupStoreAction` (as planned here), plus `switchAccountAction`
  (a sign-out like `logout`) and `endImpersonationAction` (both plain `<form action>`s, which React types as returning
  void). The step-up actions run inside `userAction` (`stepUpWithTotp(ctx, code)`). Side effect: a field-level refusal
  of `/reset` or `/invite` now passes the form's DB bucket first.
- Filed by: maintainer (T2 review F9) · Owners: C0b (`scripts/qa/tenancy-lint.ts`, its allow list), maintainer (the action files once T2 is merged)
- Files: the T2 server actions listed below; C0b's tenancy-allow list

## What

1. **L7 (applied):** `src/app/(public)/actions.ts` no longer imports `@/lib/db/client` / `@/lib/db/schema`; the
   language menu's account write is `updateOwnLocale` in `src/lib/auth/profile.ts`.
2. **L9 (at the C0b merge):** these exported `"use server"` functions do not start with `return <wrapper>(`. Each one
   already runs `assertActionOrigin()` (or the gate) first, so nothing is open today:
   - `src/lib/auth/actions.ts`: `logout`, `endImpersonationAction`, the `stepUp*Action` functions
   - `src/app/(public)/actions.ts`: `setLocaleAction` (signed-out visitors too: no `userAction`)
   - `src/app/(public)/login/verify/actions.ts`, `signup/actions.ts` (2), `invite/[token]/actions.ts` (2),
     `reset/[token]/actions.ts`
   - `src/app/app/account/actions.ts` (2), `src/app/app/account/two-factor/actions.ts` (4), `src/app/app/new/actions.ts`
   - `src/app/admin/(auth)/setup/actions.ts`, `src/app/admin/(auth)/setup/store/actions.ts` (behind the gate)

   When C0b's lint lands, the maintainer restructures each into `return userAction|publicAction|platformAction(...)`
   with the FormData parsed inside the wrapper and the redirect issued after it (or by the client), and asks C0b for
   explicit tenancy-allow entries for the ones that cannot take a wrapper: `logout` (must work with an ended
   session), `setLocaleAction` (signed out or in), and the two setup actions (the first-run gate).

## Why

The restructure changes the redirect and `useActionState` flow of every public auth form (sign-in, 2FA, signup,
invite accept, reset). Doing it before the lint exists means doing it blind, and the hand-written origin checks
already close the hole the rule guards against.

## Effect on others

- C0b: `npm test` fails on L9 until this lands; the merge of C0b and this restructure go in one maintainer step.
