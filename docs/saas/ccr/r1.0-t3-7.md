  `sendConversionsAfterResponse` call land at the T4 merge). Item 3's `versionDoc(versionId)` reads store #1 since
  fa880e4. Since the T3 review fixes (finding 2) main no longer relies on T4 landing items 1 and 2 in lockstep: an
  interim fail-safe keeps every store but #1 away from the platform-global integrations (`selectSyncBatch` and
  `pullStatuses` in `src/lib/sheets/sync.ts` read store #1's orders only; `syncSheetAfterResponse` and the order route's
  `sendConversionsAfterResponse` call run for store #1 only, `usesLegacyIntegrations` in `src/lib/orders/http.ts`).
  T4 removes the guard in the commit that lands its per-store sync and the scoped CAPI dispatch.

- Files: `src/lib/sheets/sync.ts`, `src/lib/orders/{conversions.ts, conversions-core.ts, index.ts}`,

## What

T3's R1.0 step "public-orders-runtime" moved the public order, lead, event and upsell path into the store of the
resolved page key (ORD-01 … ORD-07, ORD-17, ORD-18, ORD-21, D54, D72). Two of its after-response jobs still call
T4's single-tenant functions, and a few signatures T4's files re-export changed.

1. **Sheets push per store (ORD-08, SHT-02).** `src/lib/orders/http.ts` now calls
   `syncSheetAfterResponse(scope, label)` with the order's store. Please add the per-store sync

   ```ts
   export function syncPendingOrders(scope: StoreScope, opts?: SyncOptions): Promise<SyncResult>;   // the store's sheet, the store's pending rows
   ```

   (the single-tenant form may stay deprecated until your cron loop moves). When it exists, T3 (or the maintainer at
   the integration) changes the one line in `syncSheetAfterResponse` to `syncPendingOrders(scope, { maxRetries: 2 })`.
   Test orders never reach it: their `sheet_status` is `disabled` and the routes skip the push.

2. **Server-side Purchase per store (PIX-01, PIX-02).** The order route still calls
   `sendConversionsAfterResponse(result.conversion)`. Please add the scoped form

   ```ts
   export function sendConversionsAfterResponse(scope: StoreScope, c: PurchaseConversion | null | undefined): void;   // the store's tracking_secrets and pixel_library, the store's URL for the fallback event_source_url
   ```

   and T3 passes `target.scope` from the route. `fallbackUrl` should build the page URL with `storeUrl(address,
   "/<slug>")` (the page's store), not `PUBLIC_URL/<slug>`. Test orders build no `PurchaseConversion` at all
   (`createOrderRow` hands `null` to the hooks and to the route).

3. **Changed signatures re-exported by `src/lib/orders/index.ts`** (all compile today; the old names stay):
   - `versionDoc(scope, versionId)` is the scoped form; `versionDoc(versionId)` is deprecated
     (`src/lib/admin-data/orders.ts` calls it: please pass the order's scope).
   - `resolvePageKey(pageKey, purpose)` is deprecated (a wrapper over `resolvePublicTarget` in
     `src/lib/tenancy/public.ts`, which returns the store and its public scope too). Drop the re-export when convenient.
   - `checkCaptcha(scope, target, token, ip, opts)`, `acceptUpsell(scope, input, ctx)`,
     `upsertLead(payload, { ip, target, test })` and `createOrder(payload, ctx)` with a required
     `ctx.target: PublicPageTarget` (the resolved key) and `ctx.test`.
   - New: `createOrderRow(draft, ctx)` (D72) is implemented; P4's manual v2 path inserts through it.

4. **Export allow-lists (SEC-23), optional UX only.** `originAllowed` now refuses every entry naming the platform's
   namespace (the platform, legacy and console hosts, `STORE_ROOT_DOMAIN` and every name under it, the platform's
   registrable domain) and every origin of that namespace. `normalizeAllowedOrigins` in `src/lib/export/options.ts`
   proves each entry with `originAllowed`, so the export save already refuses such entries (`invalid`) on the server
   with no change. To tell the seller why, the dialog may call `exportOriginProblem(entry)` (`"invalid" |
   "shared_suffix" | "platform" | null`, from `@/lib/orders/origin`, isomorphic) and show "This address belongs to
   the platform" for `platform`.

5. **Readers skip test orders (D54).** `orders.is_test` and `leads.is_test` are now written by the public path
   (`?sg-test=<token>` signed for the store). Your aggregate readers (dashboard counts, the order stats by page,
   exports of "real" orders) should add `eq(orders.isTest, false)` where they count; the order list may show them
   with a TEST chip.

## Why

§E.3 (every query scoped), §C.9 (order origin per store), §E.8 (store buckets), D54 (test orders), D72 (one insert).
Without 1 and 2, a store's order is pushed to the one global sheet and its Purchase is sent with the global pixel
secrets: SHT-02 and PIX-01 stay open.

## Effect on others

None on T1 / T2. The landing runtime is not affected.
