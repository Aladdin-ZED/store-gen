## What

T1 now throws two typed refusals:

- `LifecycleError` from `transitionStore` (`src/lib/tenancy/lifecycle.ts`), with
  `code: "not_found" | "forbidden" | "step_up" | "invalid" | "status_changed"`.
- `HandleError` from `renameHandle` (`src/lib/tenancy/handles.ts`), with
  `code: "forbidden" | "invalid" | "unavailable" | "too_soon" | "status_changed"`, plus `problem`
  (`format | reserved | protected`) when the code is `invalid`, and `retryAt` when it is `too_soon`.

Today `actionFailure` maps both to `server`, so the console and the owner's close and rename sheets would show the
generic error. Add these two lines before the final `console.error`. This is a diff against `seam.ts` at `776d24c`:

```ts
import { HandleError } from "./handles";
import { LifecycleError } from "./lifecycle";
// …in actionFailure, after the QuotaError line:
  if (err instanceof LifecycleError) return { ok: false, error: err.code === "status_changed" ? "status_changed" : err.code };
  if (err instanceof HandleError) {
    if (err.code === "invalid") return { ok: false, error: `handle_${err.problem ?? "format"}` };
    if (err.code === "unavailable" || err.code === "too_soon") return { ok: false, error: `handle_${err.code}` };
    return { ok: false, error: err.code === "status_changed" ? "conflict" : err.code };
  }
```

The guard paths (`storeGuard`, `requireStoreMember`) need nothing: the lifecycle and rename writes run inside actions.

follows `shell.limit.brand_protected` (platform.md).

## Why

§A.5.1 and PLA-§8.0 rely on these refusals: a stale `from` answers `status_changed`, and a missing step-up answers
`step_up` so the step-up sheet opens. §C.7 needs the rename sheet to tell a seller why a handle was refused, without
ever saying who holds it.
