# r1.0-t4-4: the pixel library migration runs inside the store #1 conversion, scoped

- Status: superseded by T1 (CCR r1.0-t1-3 item 3): the store #1 conversion carries its own port of the migration
  (`convert.server.ts` step 3d) and `src/instrumentation.ts` no longer calls it. As r1.0-t1-3 item 3 asks, 7ffbc8c
  deletes `src/lib/pixels/migrate.server.ts` (T4's scoped form and the deprecated boot form; the pure `collectPixels`
  / `migrationLabel` of `migrate.ts` stay) and replaces the migration block of `scripts/qa/pixels-publish-check.ts` by
  a seed of store #1's converted library. test:migrate covers the migration (141 checks).
- Filed by: T4 · Owner of the files: T1
- Files: src/instrumentation.ts, src/lib/tenancy/convert.server.ts

## What

1. `src/instrumentation.ts`: remove the boot call of the store-less migration (lines 68-75 today):

   ```diff
   -      // pixel library migration (docs/OFFERS.md §A.6): one-time, idempotent, marker written last
   -      try {
   -        const { migratePixelLibrary } = await import("./lib/pixels/migrate.server");
   -        const px = await migratePixelLibrary();
   -        if (px.ran) console.info(`[boot] pixel library created: …`);
   -      } catch (err) {
   -        console.error("[boot] pixel library migration failed:", err instanceof Error ? err.message : err);
   -      }
   ```

2. `convertLegacyStore()` step 3 (§D.8), before step 5 deletes the legacy `pixels` key:

   ```ts
   import { migratePixelLibrary } from "@/lib/pixels/migrate.server";
   const px = await migratePixelLibrary(systemScope(ctx, STORE1), { legacyPixels: legacyRows.pixels ?? null });
   if (px.ran) console.info(`[boot] pixel library of store #1: ${px.entries} pixel(s), ${px.tokensCopied} token(s) copied, ${px.testCodesDeactivated} test code(s) deactivated.`);
   ```

   Signature (src/lib/pixels/migrate.server.ts, T4):
   `migratePixelLibrary(scope: WriteScope, opts?: { legacyPixels?: unknown }): Promise<MigrationResult>`. It reads the
   store's pages, versions and exports and the store's `tracking_secrets` (`getStoreSetting`), writes
   `tracking_secrets`, `pixel_health`, then `pixel_library` through `setStoreSetting` (the marker, written last), and
   audits `pixels.library_migrated` in the store. A store that already has a `pixel_library` row (copied by the 0004
   SQL from an install that ran the migration before) is left as it is.

## Why

PIX-07 (§D.8 step 3): the migration is store #1's only, reading the legacy platform `pixels` key once; new stores
never run it. The store-less form kept for today's boot call runs it for store #1 when that store exists, so the two
are equivalent, but the conversion task is the one place that still holds the legacy `pixels` value.

## Effect on others

- None on frozen contracts.
- The deprecated `migratePixelLibrary()` (no arguments) stays until this is applied; the maintainer deletes it at the
  R1.0 integration.
