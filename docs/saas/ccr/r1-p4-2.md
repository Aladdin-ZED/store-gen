# r1-p4-2: the orders barrel drops `updateOrderStatus` (P0b P4-4)

- Status: applied at the P4 merge (main): the barrel no longer exports `updateOrderStatus` / `UpdateStatusResult`. Deferred to the integration: deleting the function from `admin.ts` with its two `ops-db-check.ts` lines and the tenancy-check line (they import `admin.ts` directly and still pass).
- Filed by: P4 CALL CENTER · Owner of the file: maintainer (core §K.3)
- Files: src/lib/orders/index.ts

## What

```diff
 export {
   listOrders,
   getOrder,
-  updateOrderStatus,
   requeueOrderSync,
   ...
   type Actor,
-  type UpdateStatusResult,
 } from "./admin";
```

After the barrel no longer exports it, P4 deletes `updateOrderStatus`, `UpdateStatusResult` and `LEGACY_GRANTS` from
`src/lib/orders/admin.ts` (OPE-§3.7) and the `updateOrderStatus(B, A's order)` line of `scripts/qa/tenancy-check.ts`'s
repository suite goes with it (the maintainer's file: same CCR). `transitionOrder`, `applyExternalStatus` and
`moveToLegacy` are imported from `src/lib/orders/transition.ts` directly (server-only); no barrel export is needed.

## Why

- OPE-§3.7: `updateOrderStatus` is deleted; the status menu calls `moveToLegacy(ctx, id, label, expectRev)`.
- P0b P4-4 deferred the barrel line to P4 "once P4's `orders/actions.ts` no longer calls it". Since step 2,
  `src/app/app/[store]/orders/actions.ts` calls `moveToLegacy` and nothing in `src/**` calls `updateOrderStatus`.
- Until the CCR lands, `updateOrderStatus` stays as a thin wrapper over `moveToLegacyAs` (no direct status write;
  `test:ops`'s writer lint proves it), so the barrel and the tenancy suite keep compiling and passing.

## Effect on others

- None in `src/**` (no caller). `scripts/qa/tenancy-check.ts` line `same(fx, "updateOrderStatus(B, A's order)", …)`
  is removed with the export; `scripts/qa/tenancy-cases/ops.ts` attacks `moveToLegacy` and `transitionOrder` instead.
