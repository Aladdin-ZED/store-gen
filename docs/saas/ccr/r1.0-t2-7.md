# r1.0-t2-7: the proxy's device marker uses T2's cookie name

- Status: applied in fa880e4 (T3 merge): `src/lib/edge/device.ts` (the proxy's writer) re-exports T2's `DEVICE_COOKIE` /
  `DEVICE_COOKIE_MAX_AGE_SEC` and validates with `DEVICE_MARKER_RE`; no second spelling is left.
- Filed by: T2 · Owner of the file: T3
- Files: src/proxy.ts

## What

§B.1 / SEC-12: the proxy sets the device marker on every area-`auth` GET response that arrives without one (128-bit
random, base64url, `HttpOnly; Secure; SameSite=Lax; Path=/`, 400 days). T2 reads it and, as the fallback, sets it from
`publicAction`. Please take the name, format and lifetime from T2's constants so the two writers never differ:

```ts
import { DEVICE_COOKIE, DEVICE_COOKIE_MAX_AGE_SEC, DEVICE_MARKER_RE } from "@/lib/auth/config";
// DEVICE_COOKIE = IS_PROD ? "__Host-sgd" : "sgd"   (the `__Host-` rule of §C.9, like the session cookie)
// value: randomBytes(16).toString("base64url") → 22 characters, DEVICE_MARKER_RE = /^[A-Za-z0-9_-]{22}$/
// set only when the request has no cookie of that name matching DEVICE_MARKER_RE
```

## Why

A second spelling (or a 43-character value) would make every signup look like a new device to `scoreSignup` and
leave the `device` identity links empty (PLA Q.3).

## Effect on others

None beyond the proxy: `qa:edge-sim`'s `__Host-` assertion already covers the name in production.
