# r1.0-t4-1: the public order route sends its Purchase events with the target's scope

- Status: open
- Filed by: T4 · Owner of the file: T3
- Files: src/app/api/public/order/route.ts

## What

Once `resolvePublicTarget` hands the order route a `PublicTarget & PageTarget` (§E.2, ORD-01), pass the target's
scope to the CAPI send:

```diff
-    sendConversionsAfterResponse(result.conversion);
+    sendConversionsAfterResponse(target.scope, result.conversion);
```

`src/lib/orders/conversions.ts` (T4) already exports the scoped overload:

```ts
export function sendConversionsAfterResponse(scope: StoreScope, c: PurchaseConversion | null | undefined): void;
/** @deprecated store-less (global settings) */
export function sendConversionsAfterResponse(c: PurchaseConversion | null | undefined): void;
```

The scoped form loads the order's store's `tracking_secrets` and `pixel_library` (`getStoreSettings(scope, …)`) and
builds the fallback `event_source_url` with `storeUrl(store, "/<slug>")`. Nothing else in the route changes.

## Why

PIX-01 / PIX-02 (§D.10 `tracking_secrets` per store; §E.3): the store-less form reads the global settings, so once a
second store exists, store B's order firing a pixel id that store A also uses would be sent with A's token (dataset
poisoning, customer data sent to another tenant), and the fallback URL would be the platform's `PUBLIC_URL/<slug>`.
T4 owns the sender; only the caller knows the order's store.

## Effect on others

- None on frozen contracts (payload v2, runtime config v2, PageDoc v2, PHP export, the landing chunk).
- The deprecated store-less overload stays until this is applied; the maintainer deletes it at the R1.0 integration
  (with `adminAction` / `adminGuard`), at which point any remaining store-less call fails to compile.
- OPE-§20.4 (P5) later moves the send into the `capi` outbox handler; that handler gets the scope from
  `runOrderHooks("created", "afterCommit", scope, …)` and calls the same scoped sender.
