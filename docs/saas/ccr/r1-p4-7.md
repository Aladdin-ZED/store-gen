## 1. `HealthInputs.ops`

### What

Add one optional, additive field to the frozen `HealthInputs` (src/lib/health/types.ts) and fill it in P1's
`collectHealthInputs` from P4's reader:

```ts
// src/lib/health/types.ts
import type { OpsHealthFacts } from "@/lib/callcenter/health.server";
export interface HealthInputs {
  // …
  /** opsHealthFacts (P4): counts and Kpis of the call centre, never a customer field */
  ops?: OpsHealthFacts | null;
}

// src/lib/health/inputs.ts (P1), inside collectHealthInputs, with the other sources (a failure leaves it null)
ops: await opsHealthFacts(scope).catch(() => null),
```

`src/lib/contracts/r1-p0.ts` keeps asserting the other keys; the new key is optional, so no caller breaks.

### Why

OPE-§27.2's ten R1 `ops:*` rules need live agents, callbacks overdue, the to-pack age, holds, the delivery lane,
claims and sheet labels. The frozen `orders` field carries `orderKpis` and four counts only. Meanwhile
`src/lib/health/rules/ops.ts` reads `inputs.ops` when present and otherwise loads `opsHealthFacts(scope)` itself
(cached 60 s per store, one pass shared by the ten rules), so nothing is blocked. With the field, the read joins P1's
one pass per store and each rule's `collect` is pure (well under 40 ms).

## 2. One platform statement for `ops.presence`

### What

`scripts/qa/tenancy-allow.json` pins `src/lib/jobs/**` at 0 `tenancy: platform` queries. OPE-§J and core §H.2 slot 7
describe `ops.presence` as one statement (`// tenancy: platform presence sweep`). Add a pin:

```json
{ "files": ["src/lib/jobs/tracks/ops.ts"], "max": 1, "reason": "OPE-§J ops.presence: the one presence sweep (agent_profiles silent > 15 min, store ids only); each store's writes go through systemScope" }
```

and P4 replaces the per-store read in `presenceSweep` with:

```ts
// tenancy: platform presence sweep (agent_profiles silent > 15 min; the store ids, then each store through systemScope)
const stale = await db.selectDistinct({ storeId: agentProfiles.storeId }).from(agentProfiles)
  .where(and(ne(agentProfiles.presence, "offline"), or(isNull(agentProfiles.lastSeenAt), lt(agentProfiles.lastSeenAt, cutoff))));
```

### Why

Until then the job visits every active store each tick (one indexed read on `ap_presence_idx` per store, round-robin
cursor, 1 s budget), which is correct and inside the lint, but costs one query per store per tick.
