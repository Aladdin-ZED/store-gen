# r1.0-t2-2: the seam's `rate` option and C0b's `Bucket` builders

- Status: forwarded to C0b (`src/lib/security/rate-limit.ts`; T2 merged first, in 6ae3e7b). Item 2: the maintainer
  makes the one-line switch `storeBucketKey(...)` → `storeBucket(ctx.scope, rate.name, key)` in `chargeRate`
  (`src/lib/tenancy/seam.ts`) as part of the `string`-overload removal at the C0b merge.
- Filed by: T2 · Owner of the file: maintainer (C0b)
- Files: src/lib/security/rate-limit.ts

## What

The `rate` option of `storeAction` (§E.2) charges `s:<storeId>:<name>[:<userId>]` (§E.8). C0b's builders are not
in T2's base, so the seam builds the string itself (`storeBucketKey` in src/lib/tenancy/seam.ts) and calls today's
`rateLimit(bucket: string, …)`. Two requests for C0b's `storeBucket` / `platformBucket`:

1. **Multi-segment names.** The §E.8 table uses names with colons (`sheets:connect`, `ai:report`, `login:acctnet`,
   `media:upload`, `invite:accept:ip`). Accept them: `name` = `/^[a-z][a-z0-9_-]*(?::[a-z0-9_-]+)*$/`, at most 48
   characters, the whole bucket at most 191 characters (throw beyond, never truncate: today's
   `bucket.slice(0, 191)` could merge two buckets). `storeBucketKey` applies exactly these rules, so the switch is
   byte-identical.
2. **Order at the integration.** When C0b merges, T2 replaces `storeBucketKey(...)` with
   `storeBucket(ctx.scope, rate.name, key)` in its own file (one line). The removal of the deprecated `string`
   overload at the R1.0 integration must come after that switch; if T2 merges first and C0b later, the maintainer
   makes the one-line switch in `chargeRate` (src/lib/tenancy/seam.ts) as part of the overload removal.

## Why

Without (1) a seam caller such as `rate: { name: "sheets:connect", … }` would throw at the builder. Without (2) the
integration breaks `tsc` (lint L5 turns on with the overload removal).

## Effect on others

None until C0b merges. Bucket strings are unchanged by the switch (same format), so no live bucket resets.
