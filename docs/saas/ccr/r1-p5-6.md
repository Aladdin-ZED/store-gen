## What

Core §H.2 slot 1 and OPE-§19.7 define `pending_sheets` as "bound and enabled and (`sheet_status` pending / failed past
backoff, or `sheet_dirty > 0`, or a pull due)". Today's predicate (R1.0 shape) has three gaps:

| Gap | Effect today | Who pays |
|---|---|---|
| no binding check | a store whose sheet is not in `sheet_bindings` is visited; `pushStore` answers `skipped: "unbound"` with no Google call | one cheap visit per tick |
| `failed` regardless of the backoff | a store whose failed orders are all backing off is visited and ranked by them; its run selects nothing and makes no call | one cheap visit, and it sorts ahead of stores with due work |
| no `sheet_dirty > 0` branch | a store whose only work is dirty synced rows (an admin status change, a P4 transition) is visited only through the "pull due" branch, so with "Bring status changes back" off its status cells wait for the next new order | the store's agents (a stale sheet) |

The third gap is the one that matters: OD2 says a status write never waits for Google, and the `after()` push covers the
request-time path, but a dirty row whose `after()` push was cut (quota, breaker, a restart) has no tick to finish it.
