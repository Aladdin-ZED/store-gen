# r1-p7-12: the tenancy page sweep and the seam-gated AI component harness page

- Status: open
- Filed by: P7 (step 11) · Owner: maintainer (scripts/qa/tenancy-check.ts, core §K.3)
- Files: scripts/qa/tenancy-check.ts (`pageSuite`)

## What

Step 11 adds `src/app/app/[store]/settings/ai/harness/page.tsx`, the in-flow AI component harness of the P7 brief
(ai.md AI-§Q.3, the `qa:wizard-e2e` harness steps). By the brief it answers `notFound()` unless the `ai-harness`
test seam is on (`testSeam("ai-harness")`: SG_E2E=1, SG_AI_HARNESS=1, a loopback app origin and a `cod_test_*`
database; src/lib/security/test-seams.ts), so it is never reachable on a deployed site. Only after the seam does it
call `requireStoreMember({ permission: "settings.read" })`.

`pageSuite` derives every page under `/app/[store]` and requires A's owner to render it ("A's owner renders"), and a
granted role of B on B's handle to render or redirect. `test:tenancy` runs without the seam's variables, so the
harness answers the neutral 404 to everyone, A's owner included, and two positive controls fail:

```
✗ [pages] /app/[store]/settings/ai/harness · A's owner renders
✗ [pages] /app/[store]/settings/ai/harness?… · B owner|admin|… · B's handle, A's ids: 404 or a redirect inside B
```

The attack halves pass (the 404 for everyone is stricter than the seam's own check). The page reads no store data
before the seam.

## Requested change

Treat a page whose source gates itself on a test seam before the store seam as seam-gated: the suite expects the
neutral 404 for every caller, owner included, and skips the "owner sees" and B-handle positive controls.

```ts
// pageSuite, after `const source = readFileSync(...)`
const seamGated = /if \(!testSeam\("[a-z-]+"\)\) notFound\(\);/.test(source) && source.indexOf("testSeam(") < source.indexOf("requireStoreMember(");
if (seamGated) {
  for (const who of [{ userId: fx.A.members.owner, label: "A owner" }, ...attackers(fx)]) {
    const r = await renderPage({ userId: who.userId }, page, { store: fx.A.handle });
    check(`${page.template} · ${who.label} · seam off: 404`, r.kind === "notFound", r);
  }
  continue;
}
```

## Why not in P7's files

`pageSuite` and its page derivation are the maintainer's (core §K.3); a case file can add route and action cases, not
exempt a page. Meanwhile the page follows the brief exactly and P7's suites are unaffected.
