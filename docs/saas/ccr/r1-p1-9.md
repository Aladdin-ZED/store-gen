## 1. The R1.0 exit e2e opens the deleted `/admin` home (maintainer, `scripts/qa/e2e/r1.0-exit.ts`)

### Why

PLA-§4.1 deletes `src/app/admin/page.tsx` when `(console)/page.tsx` lands (both resolve to `/admin`). Step 8 does that,
with the two components only it used (`src/app/admin/(auth)/_components/{invite-code-form,view-as-form}.tsx`). Step
d) of the R1.0 exit e2e (`r1.0-exit.ts:880-890`) still goes to `/admin` and fills `#invite-codes`, which the overview
does not render: the invite code form moves to `/admin/settings/signup?tab=codes` (PLA-§13, P1 step 12).

### What

Point step d) at the console's invite code flow once P1 step 12 lands (the codes tab of `/admin/settings/signup`, the
same `createInviteCodeAction` underneath), or keep it on `/admin/settings/signup?tab=codes&new=1`, the target of the
console ⌘K action "New invite code". Until then `qa:r1-exit` step d) fails at `form.waitFor()`; `npm test` is
unaffected (the e2e is not chained).

## 2. P2's primitives the console renders before P2's bodies land (P2)

### Why

Step 8 imports `KpiTile`, `PanelBoundary`, `Monogram` and `StatusPill` from `src/components/admin/common/` with the
PLA-§22.12 props. Their P0b stubs render unstyled elements with no `class` attribute. So the screens stay readable on
`r1/p1`, `src/components/console/shell/console.module.css` lays the stubs out with zero-specificity rules scoped by
`:not([class])`. P2's bodies carry classes, so the rules stop matching on the P2 merge and nothing needs removing.

### What

1. `PanelBoundary` (frozen props `{ title, children }`) has no skeleton slot: the console nests its own
   `<Suspense fallback={<PanelSkeleton … />}>` inside it. P2's error boundary with Retry and the reference is the outer
   net; the console's read models already turn a failing query into the panel's own error state (`panel()` in
   `src/lib/platform/panel.ts`), so both paths show "This panel couldn't load", Retry and the 8-character reference.
2. `EmptyState` (`src/components/admin/common/empty-state.tsx`, R1.0) has no quiet variant and still renders
   `adm-aurora adm-grain`, which PLA-§4.7 rule 4 forbids in the console. The console uses its own `QuietEmpty`
   (`src/components/console/panel.tsx`: one sentence, one action) until P2 ships the quiet variant (P2-13 removes the
   two classes); the verify step swaps it if P2's variant has the same shape.

## 3. `useChords()` (P2, `src/components/admin/shell/chords.ts`)

PLA-§4.7 rule 2 names one shared hook. It is not on this branch, so the console uses a local copy with the builder's
`isEditable` / `overlayOpen` rules (`src/components/console/_compat/chords.ts`, the brief's last resort). Contract the
copy follows, so P2's hook can replace it by an import swap:

```ts
export interface Chord { keys: string /* "g o" (a sequence) or one key ("?", "/") */; run(): void }
export function useChords(chords: readonly Chord[]): void;   // ignored with Meta/Ctrl/Alt, in editable fields and while an overlay is open
```

## 4. The console token block (P2, `scripts/build-admin-css.mjs` `SURFACES.console`)

`console.module.css` `.tokens` carries the DES-§16.2 console input (base hue 230 at chroma 0.008, teal accent 205 at
0.09, the deep-ink sidebar of DES-§16.11), scoped to the shell root and to `<body>` while the console is mounted so
portalled layers read it. When P2's generator emits `[data-surface="console"]`, the module's `.tokens` block can be
dropped in the verify step; the values were taken from the same table, every hue outside 25-75°.
