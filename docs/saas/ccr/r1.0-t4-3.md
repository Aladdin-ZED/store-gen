# r1.0-t4-3: the secrets check tests the store export key, not the removed platform export key

- Status: open
- Filed by: T4 · Owner of the files: maintainer (no R1.0 track lists them)
- Files: scripts/qa/secrets-check.ts, docs/DEPLOY-HOSTINGER.md, docs/GOOGLE-SHEETS-SETUP.md

## What

1. `scripts/qa/secrets-check.ts` §3 "PHP export key": replace the env-driven `exportServiceAccount()` cases by the
   pure functions of `src/lib/export/service-account.ts` (T4) that PHP exports now use:

   ```ts
   import { exportKeyState, parseServiceAccountKey, INVALID_EXPORT_KEY, NO_EXPORT_KEY, SAME_AS_APP_KEY } from "@/lib/export/service-account";

   process.env.GOOGLE_SA_JSON_B64 = b64(appKey);
   check(exportKeyState(null).problem === NO_EXPORT_KEY, "no store key → nothing can be embedded (never the app's key)");
   check(exportKeyState(parseServiceAccountKey(JSON.stringify(appKey))).problem === SAME_AS_APP_KEY, "the app's own key is refused as a store export key");
   check(exportKeyState(parseServiceAccountKey(b64(keyJson(appKey.client_email, "app-key-2")))).problem === SAME_AS_APP_KEY, "another key of the app's own service account is refused");
   check(exportKeyState(parseServiceAccountKey(b64({ ...appKey, client_email: "renamed@…", private_key_id: "other" }))).problem === SAME_AS_APP_KEY, "the app's private key under another e-mail is refused");
   check(parseServiceAccountKey("bm90IGEga2V5") === null, "an invalid key is not parsed (the settings card answers INVALID_EXPORT_KEY)");
   const ok = exportKeyState(parseServiceAccountKey(b64(exportKey)));
   // … the existing "minimal fields" / "not the app's" assertions on ok.key, unchanged
   ```

   and add `export_key` to the checked secret store keys (§F.10: "gains the new key names").

   The two README assertions at the end name the old brand, which the README no longer carries (EXP-07: the tool is
   named by `platform.brand.name`, "Store Gen" by default; the platform's key is "the platform's own key"):

   ```diff
   -check(withKey.includes("every row") && withKey.includes("not COD Studio's own key"), "README says what the embedded key can reach");
   +check(withKey.includes("every row") && withKey.includes("not the platform's own key"), "README says what the embedded key can reach");
   …
   -check(withoutKey.includes("never COD Studio's own") && withoutKey.includes("delete the key you uploaded"), "README (own key) warns against the app's key and explains revocation");
   +check(withoutKey.includes("never the platform's own key") && withoutKey.includes("delete the key you uploaded"), "README (own key) warns against the app's key and explains revocation");
   ```

   Until this is applied, `npm run qa:secrets` (in `npm run gate`, not in `npm test`) reports exactly these 2 of 54
   checks as failed; the other 52 pass.
2. Docs: `GOOGLE_EXPORT_SA_JSON_B64` is removed (§H.7, EXP-03). In `docs/DEPLOY-HOSTINGER.md` drop its row; in
   `docs/GOOGLE-SHEETS-SETUP.md` Part C, the key is pasted per store in **Settings → Google Sheets → Key for PHP
   exports** (encrypted, write-only; the platform's own key is refused there).

## Why

EXP-03 / §F.10: a PHP export embeds only the store's own export key (`export_key`), never a platform key. No export
path reads `GOOGLE_EXPORT_SA_JSON_B64` any more; `exportServiceAccount()` survives only, `@deprecated`, so today's
secrets check keeps compiling and passing.

## Effect on others

- None on frozen contracts. The PHP export format (config.php fields, order.php) is unchanged; only where the key
  comes from changed.
- Once applied, T4 deletes the deprecated `exportServiceAccount()` (or the maintainer does at the R1.0 integration).
