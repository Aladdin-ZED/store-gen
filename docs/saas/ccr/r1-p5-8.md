# r1-p5-8: `test:tenancy` special cases of the R1.0 Sheets connect and pull, moved to R1's bindings and one read

- Status: open (apply at the P5 merge; verified: with this diff `test:tenancy` passes 6626 / 0 failed on r1/p5 step 5)
- Filed by: P5 · Owner of the file: maintainer (`scripts/qa/tenancy-check.ts`, core §K.3)
- Files P5 changed: `src/lib/sheets/{connect,push,pull,bind-legacy,sync}.ts`, `src/app/api/app/[store]/sheets/{connect,verify}/route.ts`

## Why

Step 5 delivers OPE-§19.2 / §19.3 / §19.6 and core §E.8. Six R1.0 special cases of `test:tenancy` assert the R1.0
behaviour this replaces; without the diff they fail (6613 passed, 6 failed):

| Case | R1.0 expectation | R1 (this step) |
|---|---|---|
| sheet with A's order ids pulled for B: read, 0 updated | `pullStatuses` reads `GET …/values/Commandes!A2:C` | the pull rides on the push's one `values:batchGet` (header N1:AZ1 + A2:<width>); the fake answered it with the spreadsheet's metadata, so 0 rows were seen |
| cron tick: a store with no order to push still has its statuses pulled (SHT-11) | same read | same: the fake gains `values:batchGet` |
| B pasting A's sheet link gets a proof code, not a connection | 200 + a proof code | A holds the `sheet_bindings` row: 409 `binding_conflict`, the one generic message, before any Google call (OPE-§19.3) |
| B pasting A's link with a fresh step-up: a proof code (T4 review) | 200 + a proof code, then the code planted in A's cells | same refusal; the planted-code control (SHT-09: no cell is ever read for the proof) moves to a spreadsheet no store holds |
| B verifying without the code in the sheet: refused | 409 | 429: start, verify and disconnect now share `s:<sid>:sheets:connect:<uid>` at 10 per hour (§E.8), which the routes suite spends first; the cases open a fresh window |
| B's own new spreadsheet: a proof code (T4 review) | 200 | 429 for the same reason |

Nothing is weakened: every R1.0 assertion keeps its intent (no store reaches another store's sheet or orders, a code in
a cell proves nothing, the cron pulls a store with nothing to push), and the refusal adds "no proof code, no Google call".
