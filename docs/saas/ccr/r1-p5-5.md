# r1-p5-5: the Sheets "Statut livraison" cell reads P4's `ops.ship.<state>` keys

- Status: open (a note: no change to a frozen file; P4 confirms when it ships its catalog)
- Filed by: P5 · Owner: P4 (`src/lib/i18n/admin/{en,fr,ar}/ops.ts`, the `ops.` prefix, D67)
- Files P5 wrote: `src/lib/sheets/row.ts` (`shipStateLabel`, `r1Values`), `src/lib/sheets/plan.ts`

## What

OPE-§19.4 (rev 3) mirrors the exact ship state into the optional sheet header "Statut livraison" as "`ops.ship.<state>`
in the sheet's locale". P5 reads it with `messageOf(\`ops.ship.${state}\`, locale)` (src/lib/i18n/admin/index.ts):

| Ship state | Cell while P4's key is missing | Cell once P4's key exists |
|---|---|---|
| `none` | empty (nothing shipped yet) | empty (P5 never writes a label for `none`) |
| `to_pack`, `packed` | the projection's legacy label ("Confirmée") | `ops.ship.to_pack`, `ops.ship.packed` |
| `shipped`, `in_transit`, `delivered`, `refused`, `returned`, `lost` | the legacy French label of the same status (`ORDER_STATUSES`) | `ops.ship.<state>` |
| `out_for_delivery`, `attempt_failed`, `postponed` | the projection's legacy label ("En livraison") | `ops.ship.<state>` ("Tentative échouée", "Reportée"…) |

## Asks to P4

1. Name the keys exactly `ops.ship.<state>` for the eleven states other than `none` (the `SHIP_STATES` ids of
   src/lib/orders/state.ts), in en, fr and ar. No placeholder: the cell is plain text.
2. The fr values are what sheet teams read in the cell; keep them short (≤ 30 characters, no em dash).

Nothing changes on P5's side when the keys arrive: `shipStateLabel` prefers them automatically, and
`src/lib/sheets/selftest.ts` checks the cell through an injected label function, so it does not depend on P4's
wording.
