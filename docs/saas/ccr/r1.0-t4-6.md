# r1.0-t4-6: the publisher resolves only the page's own store's assets

- Status: open
- Filed by: T4 · Owner of the file: T3
- Files: src/lib/render/publish.server.ts

## What

Every asset lookup of the renderer goes through the scoped read of `src/lib/media/assets.ts` (T4):

```ts
export async function getAssetsByIds(scope: StoreScope, ids: readonly string[]): Promise<AssetRecord[]>;
/** @deprecated store-less: any store's rows */
export async function getAssetsByIds(ids: readonly string[]): Promise<AssetRecord[]>;
```

In the scoped publish and render paths (`publishPage(scope, …)`, `renderAndCommit(scope, …)`, the legal pages):

```diff
-export async function liveResolverFor(doc: PageDoc, store: StoreInfo): Promise<AssetResolver> {
-  const rows = await getAssetsByIds(collectAssetIds(doc, [store.logo]));
+export async function liveResolverFor(scope: StoreScope, doc: PageDoc, store: StoreInfo): Promise<AssetResolver> {
+  const rows = await getAssetsByIds(scope, collectAssetIds(doc, [store.logo]));
   return liveAssetResolver(rows);
 }
```

and the same for the store logo of the legal page render (`publish.server.ts:669` today):

```diff
-  const rows = store.logo ? await getAssetsByIds([store.logo.id]) : [];
+  const rows = store.logo ? await getAssetsByIds(scope, [store.logo.id]) : [];
```

The public target's scope (`resolvePublicTarget`, kind `public`) is a `StoreScope`, so the serving path passes it
as it is.

## Why

MED-18 / §E.3 rule 5: a document of store B that names an asset id of store A (pasted JSON, an import, a forged
save) must render as if the image were missing, never with A's file. Since D21 ids are per store, the scoped read
answers another store's id exactly like a deleted one. The builder (`src/lib/editor/pages.server.ts`), the exporter
(`src/lib/export/server.ts`) and the generator already resolve through the scoped form; the publisher is the last
store-less caller.

## Effect on others

- None on frozen contracts: PageDoc v2, runtime config v2 and the landing chunk are unchanged; a page whose assets
  are all its store's own (every page after the store #1 conversion) renders byte-identical HTML.
- The deprecated store-less overload stays until this is applied; the maintainer deletes it at the R1.0
  integration, after which a store-less call fails to compile.
