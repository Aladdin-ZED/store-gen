## What

1. **Edge lifetime apart from the browser's (applied).** `/media/<key>` keeps `Cache-Control: public,
   max-age=31536000, immutable` for browsers and adds `CDN-Cache-Control: public, max-age=86400`. Cloudflare honours
   `CDN-Cache-Control` over `Cache-Control` for its own copy, so the zone's "cache everything" rule on `/media/*` keeps
   a file at most a day.
2. **§G.6:** after "with today's headers (`immutable`, ranges, sandbox CSP, nosniff, CORP)" add: "plus
   `CDN-Cache-Control: public, max-age=86400` (the edge copy lives a day at most, the browser's a year; R1.0 review of
   T3, finding 7). The Cache Rule on `/media/*` must not set an Edge TTL override that ignores origin headers."
3. **§A.5.3 and the lifecycle transitions:** the transitions to `suspended`, `closed` and `scheduled_deletion`, the
   purge, and a D76 takedown enqueue a `cf_purge` job: purge-by-URL of `https://<PLATFORM_HOST>/media/<key>` for every
   `media_files.key` of the store (30 URLs per Cloudflare API call, the platform's API token with the "Cache Purge"
   permission only, retried with backoff, logged as `error_events` area `edge`, code `purge_failed`). Until the token
   is configured, item 1 bounds the exposure to a day.

## Why

T3 added the §A.5.3 status check to `/media/<key>`: a suspended, closed or deleted store's key answers the unknown-key
404. But the route answered `immutable` for a year and §G.6 puts a Cloudflare "cache everything" rule on `/media/*`,
so the origin's 404 was never consulted: the media of a store taken down after an abuse report kept being served from
Cloudflare's cache under the platform URL for up to a year. The browser copy cannot be recalled; the edge copy can.

## Effect on others

None on the frozen contracts (PageDoc v2, the media URL shapes, the keys). The lifecycle track gains one job kind and
needs one new secret (`CF_API_TOKEN`, `CF_ZONE_ID`; never printed, §H.7). Browser caches still keep a file a year: an
abuse takedown note in the console says so.
