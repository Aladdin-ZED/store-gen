## Why

- Core §M.5 and LAN-§3.2: "the checklist item ids equal the gate item ids, so the publish dialog is never the first
  time an item appears". The checklist (P3's `checklist.ts`) now runs the gate's own evaluator
  (`honestyItems`, src/lib/landing/honesty/gate.ts), so the panel and the server agree by construction, but only on
  the facts it is given. T4's frozen context lacks the policies (every `honesty:promise` row), the thank-you
  expectation (`thanks:*`), the confirmation-call switch, the attested proof (`honesty:D2` on unattested figures and
  the rating), the generator's snapshot (`honesty:I5`, `honesty:stock_untyped`), a typed-or-not `leadDays`
  (`delivery:lead-unset`; T4 folds null into 0) and a real zone count (T4's preload reports `count: 0` whatever the
  table holds, so the panel cannot trust a 0 while zones are on). Until this lands those rows show only in the
  dialog, after the server refuses.
- LAN-§3.2.1 and the P0b note on `originFrom`: the checklist's origin must be "the same fold of the same builder's
  output". With `gate.gen` the panel refolds `originFrom(null, doc, gen)` on every edit, so a field the owner just
  retyped turns `owner` at once (T4's `originOf` compares against the newest generation version at load time and
  marks nothing generated when no version exists, where the core's builder says `library`).

## Effect

- No change to `buildChecklist(doc, ctx: LandingCheckContext)`'s signature, to `emptyCheckData()` or to the two
  callers (`PublishDialog`, the preload): `gate` is optional and additive.
- `test:checklist` already runs the panel with `gate` on every LAN-§3.2.1 fixture (panel = gate) and without it (the
  frozen-context rows only); it stays green before and after the merge.
- The preload costs the gate's reads once per page open (≤ 9 indexed reads, the settings and zones from their caches).
- `CityKey` and `NumberClass` stop being mirrors (P3-5): `CityKey` is the one slug type of `src/lib/orders/address.ts`,
  `NumberClass` the numbers audit's own union (identical members).
