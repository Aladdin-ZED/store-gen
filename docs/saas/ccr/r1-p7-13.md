# r1-p7-13: the AI settings line of HealthInputs and the 0-point hint

- Status: open
- Filed by: P7 (step 12) · Owner: maintainer (src/lib/health/types.ts, core §K.3) and P1 (src/lib/health/inputs.ts)
- Files: src/lib/health/types.ts, src/lib/health/inputs.ts (`collectHealthInputs`)

## What

SF-03's ai rules (ai.md AI-§I.0) need two values `HealthInputs` does not carry: `store_ai.director` /
`store_ai.learning` and whether Cloud AI is on for the store. And `ai:learning_off` is a hint "with 0 points", which
`HealthIssue.points` (`3 | 6 | 10`) cannot say.

## The change

```ts
// src/lib/health/types.ts
import type { AiHealthSettings } from "@/lib/health/rules/ai"; // or inline the shape below
export interface HealthInputs {
  // …
  /** store_ai + platform_ai (P7): director, learning, cloudOn = platform_ai.enabled ∧ caps.monthlyUsd ≠ null ∧ store_ai.mode ≠ "local" */
  aiSettings: { director: "auto" | "ask" | "off" | null; learning: boolean; cloudOn: boolean } | null;
}
export interface HealthIssue {
  // …
  points: 0 | 3 | 6 | 10; // 0 = a hint: listed, never scored
}
```

P1's `collectHealthInputs` fills `aiSettings` in its read pass (`getStoreSetting(scope, "store_ai")`,
`getPlatformSetting("platform_ai")`, both cached) and `null` when the read fails. The score sums `points`, so a hint
adds nothing.

## Meanwhile

`src/lib/health/rules/ai.ts` reads `inputs.aiSettings` when present and otherwise the two settings through the scope
itself (cached reads, well under 40 ms); its fixtures pass `aiSettings`. `ai:learning_off` returns `points: 0` through
a cast named after this CCR; drop the cast and the fallback read once this lands.
