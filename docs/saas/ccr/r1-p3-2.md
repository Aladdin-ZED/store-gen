## What

### A. Pass the store's answers to the legal pages (LAN-§3.3, LD29)

P3's `LegalBody` takes an optional `policy?: LegalPolicyInput | null` (`src/landing/legal/policy.ts`), and P3's
server helper `legalPolicyFor(scope): Promise<LegalPolicyInput>` (`src/landing/legal/policy.server.ts`) reads it
through the seam: `policies`, `checkout` (`confirmationCall`, `zonesEnabled`, `lineOnLanding`), `listZones(scope)` and
`callingWindowFor(scope)`. Without it every answer reads as unset, so a legal page shows its gap lines and promises
nothing, which is honest but empty. The render paths must pass it:

1. `src/landing/document.tsx`, `LegalDocumentProps` and `LegalDocument`:

   ```diff

    export interface LegalDocumentProps {

   +export function LegalDocument({ doc, ctx, kind, updatedAt, policy = null, qa = false }: LegalDocumentProps): ReactElement {
   …
   -      <LegalBody ctx={ctx} kind={kind} updatedAt={updatedAt} />
   +      <LegalBody ctx={ctx} kind={kind} updatedAt={updatedAt} policy={policy} />
   ```

2. `src/lib/render/core.ts`, `LegalHtmlOptions` gains `policy?: LegalPolicyInput | null` and `renderLegalHtml` passes
   it: `createElement(LegalDocument, { doc, ctx, kind, updatedAt, policy: opts.policy ?? null, qa: opts.qa })`.

3. `src/lib/render/store-pages.server.ts`, `getStoreLegalDocument`: read the answers inside the loader and pass them:

   ```diff
   +import { legalPolicyFor } from "@/landing/legal/policy.server";
   …
   -      const [rc, changed] = await Promise.all([loadStoreRenderContext(scope, store, { pageId: page.pageId }), factsUpdatedAt(scope)]);
   +      const [rc, changed, policy] = await Promise.all([loadStoreRenderContext(scope, store, { pageId: page.pageId }), factsUpdatedAt(scope), legalPolicyFor(scope)]);
   ```

   `factsUpdatedAt` already reads `store` and `policies`; add `'checkout'` to its `IN (…)` list so the "updated on"
   date moves when the confirmation call changes. A save of `policies`, `checkout`, the zones or the calling window
   must drop the store's `legal` cache entries, as a `store` save does today (the `store_info` render reason of
   LAN-§8.5 names the same saves).

4. `src/lib/export/bundle.ts`: the export is a publish to someone else's server, so its legal pages carry the answers
   of the moment of export. The export's server entry (it already holds the store scope) reads
   `await legalPolicyFor(scope)` once and passes `policy` to each `renderLegalHtml(doc, kind, { … })` of the loop.
   Exports never carry the hours of a window that is not `configured` (P3's `resolveLegalPolicy` already drops them).

page, the contact page links it, and `factsOf` reads `ctx.links.returns`.

## Why

- LAN-§3.3: "`src/landing/legal/content.ts` gains a `returns` kind and reads `StorePolicyFacts`"; the legal returns page
  shows the law's line from the legal template (core D39) and the store's own answers, never an invented policy.
- LD29: `policies` is the single source of every promise; the contact page's hours come from `callingWindowFor` and
  show only while `!noShopperHours(w, now)`.
- P0b P3-4 deferred the widening to this merge because it changes exports; until then P3 keys the returns text under
  its local `LegalTextKind` and the shipping page carries the returns sections, so no page loses them.

## Effect

- Before (A), every legal page of every store reads as "every card unset": gap lines ("À compléter : nombre de
  jours"), no call promise, no inspection promise, no hours. After (A), each answer appears on its page in the page's
  language, and the gaps stay only for the cards the owner left unset (`legalPolicyGaps` lists them for the admin).
- After (B), `/policies/returns` answers 200 on every store host, and exports gain `legal/returns.html`.
- `test:policies` section 4 already proves the texts for both states (`RETURNS_SERVED` false and true read the same
  sections); the merge re-runs it with `LEGAL_KINDS` widened.
