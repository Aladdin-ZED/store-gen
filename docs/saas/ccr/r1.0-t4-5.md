# r1.0-t4-5: the chunk store's `insertFiles` writes the file's store

- Status: applied in 7ffbc8c with CCR r1.0-m-4: `insertFiles(conn, scope: WriteScope, assetId, files)` writes
  `store_id` and `storage = 'db'` on every `media_files` row; `insertStoreFiles` (files.ts) is a one-line call to it.
  `forgetMisses` moved into store.ts and is kept after the caller's commit: the in-transaction delete alone can be
  undone by a reader between the insert and the commit.
- Filed by: T4 · Owner of the file: maintainer (no R1.0 track lists it; P8 from R1 product)
- Files: src/lib/media/store.ts

## What

`insertFiles` takes the store of the asset and writes it, with the backend, on every `media_files` row:

```diff
-/** Insert files (metadata + chunks) using an open transaction connection. */
-export async function insertFiles(conn: PoolConnection, assetId: string, files: FileToStore[]): Promise<void> {
+/** Insert files (metadata + chunks) of one asset of `storeId` using an open transaction connection. */
+export async function insertFiles(conn: PoolConnection, storeId: string, assetId: string, files: readonly FileToStore[]): Promise<void> {
   const s = state();
   for (const f of files) {
     const chunks = Math.max(1, Math.ceil(f.data.length / CHUNK_SIZE));
     await conn.execute(
-      "INSERT INTO media_files (`key`, asset_id, mime, bytes, chunks, sha256) VALUES (?, ?, ?, ?, ?, ?)",
-      [f.key, assetId, f.mime, f.data.length, chunks, sha256hex(f.data)],
+      "INSERT INTO media_files (`key`, store_id, asset_id, mime, bytes, chunks, sha256, storage) VALUES (?, ?, ?, ?, ?, ?, ?, 'db')",
+      [f.key, storeId, assetId, f.mime, f.data.length, chunks, sha256hex(f.data)],
     );
```

The rest of the function, `CHUNK_SIZE` and the chunk format stay unchanged. Then T4 (or P8, who takes
`src/lib/media/files.ts`'s caller at the integration) replaces the body of `insertStoreFiles` in
`src/lib/media/files.ts` with:

```ts
await insertFiles(conn, scope.storeId, assetId, files);
```

and drops `forgetMisses` (the store's own `s.misses.delete(f.key)` covers it).

## Why

0004 made `media_files.store_id` NOT NULL with no default (§D.2, MED-09). Today's `insertFiles` omits the column, so
every upload through it fails with "Field 'store_id' doesn't have a default value". The upload pipeline (T4,
`src/lib/media/process.ts`) therefore writes its files through the adapter `src/lib/media/files.ts`, which repeats
these two statements with the store and `storage = 'db'`, and clears the 60 s miss memory itself after the commit.
Two copies of the chunk writer must not outlive R1.0: §G.1 has P8's `storage/db.ts` wrap `insertFiles` unchanged.

## Effect on others

- No frozen contract changes (the chunk format, `CHUNK_SIZE` and every read are unchanged).
- The only callers are `src/lib/media/selftest-store.ts` (T4; it already writes through the adapter) and the
  adapter itself; nothing else imports `insertFiles`.
- `media_files.storage` defaults to `'db'` anyway; writing it explicitly keeps the row's backend obvious next to
  P8's FS backend.
