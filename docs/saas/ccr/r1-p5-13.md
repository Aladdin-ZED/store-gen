# r1-p5-13: the shell maps the Connect items' icons and keywords (integrations, telegram, whatsapp)

- Status: open (P2 applies it in `src/components/admin/shell/store-nav.ts`; P5's items render with the fallback icon meanwhile)
- Owner of the change: P2 SHELL (`src/components/admin/shell/store-nav.ts`, `src/components/admin/shell/nav/t4.ts`)
- Asked by: P5 INTEGRATIONS, step 8 (`src/components/admin/shell/nav/integrations.ts`)

## What

P5's nav file contributes three new Connect items (OPE-§M.1):

| id | order | href | icon (lucide name) | permission |
|---|---|---|---|---|
| `integrations` | 5 | `/integrations` | `Cable` | `integrations.manage` |
| `telegram` | 30 | `/integrations/telegram` | `Send` | `integrations.manage` |
| `whatsapp` | 40 | `/integrations/whatsapp` | `MessageCircle` | `callcenter.configure` |

The shell's `ICONS` map knows only the R1.0 names, so these draw `CircleIcon`. The diff:

```ts
// src/components/admin/shell/store-nav.ts
import { CableIcon, MessageCircleIcon, SendIcon, /* … */ } from "lucide-react";
const ICONS = {
  // … R1.0 names …
  Cable: CableIcon,
  Send: SendIcon,
  MessageCircle: MessageCircleIcon,
};
```

and the ⌘K keywords (wherever P2 keeps `NAV_KEYWORDS` once it owns the shell):

```ts
integrations: ["health", "deliveries", "replay", "webhooks", "outbox"],
telegram: ["bot", "notifications", "chat", "alerts"],
whatsapp: ["templates", "messages", "click to chat", "quick replies"],
```

The labels are already in the catalogs (`nav.integrations`, `nav.telegram`, `nav.whatsapp` in
`src/lib/i18n/admin/{ar,fr,en}/integrations.ts`).

## Why

Core §I.3: the registry hands the shell an icon name, the shell maps it. Without the map entry the items show a
neutral circle (no crash, no wrong icon).

## Meanwhile

Nothing to do in P5: the items are in the registry and filtered by permission and release.
