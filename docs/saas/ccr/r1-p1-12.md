# r1-p1-12: the tenancy suite's console pages read every account for staff

- Status: open (nothing here blocks the step; one `test:tenancy` check stays red until it is applied)
- Filed by: P1 CONSOLE (R1 step 11, `p1-people-lookup-plans-flags-ui`) · Owner: the maintainer
  (`scripts/qa/tenancy-check.ts`, core §K.3)

## Why

Step 11 adds `/admin/users` (PLA-§11.1): the people list shows every account on the platform, each name linking to
`/admin/users/<userId>`. The suite "account and console" renders every page outside `/app/<handle>` as each attacker
of store A, including "staff without membership", and checks `nothing of A` over all four canary groups. The fresh
members that earlier suites add to A (`fresh.member(A, role)`) register their user ids as A's `ids` canaries, so the
staff attacker now finds three of them on `/admin/users`:

```
✗ [account and console] /admin/users · staff without membership: nothing of A
    ["ids:01M6QK…","ids:01M6QK…","ids:01M6QK…"]
```

Reading every account is the console's job for staff with `console.read` (PLA-§11.1, PD35: the e-mail is masked
for support and analyst, the ids are not personal data). Store members, outsiders and the member of both still get
the 404 from `requirePlatform`, and the console's own attack suite (PLA-§O.3, `scripts/qa/tenancy-cases/platform.ts`)
checks what each staff role may see. Customer, data and secret canaries must still never appear on a console page.

## What

In `scripts/qa/tenancy-check.ts`, suite "account and console", leave the `ids` group out for the staff attacker on
`/admin/**` pages only:

```diff
       const r = await renderPage({ userId: who.userId }, page, params);
       const label = `${page.template}${page.kind === "layout" ? " (layout)" : ""} · ${who.label}`;
       if (!ranReal(label, r.kind === "error" ? r : null)) continue;
-      if (r.kind === "render") check(`${label}: nothing of A`, leaks(fx, r.payload).length === 0, leaks(fx, r.payload));
+      // the console is staff's cross-store view (PLA-§11.1, §6.1): account and row ids may show on /admin/** for staff;
+      // customer, data and secret canaries never do
+      const only = who.userId === fx.staff.id && page.template.startsWith("/admin") ? (["customer", "data", "secret"] as const) : undefined;
+      if (r.kind === "render") check(`${label}: nothing of A`, leaks(fx, r.payload, { only }).length === 0, leaks(fx, r.payload, { only }));
```

No other check changes; every other attacker keeps all four groups on every page.
