# r1.0-t3-5: T4's callers move to the scoped publish, serving and stats APIs

- Status: forwarded to T4 (its callers). At the T3 merge (fa880e4) the deprecated single-tenant forms it lists
  (`publishPage(pageId, userId)`, `renderAndCommit(pageId, …)`, `publishTrackingOnly`, `storeInfo`, `liveResolverFor`,
  `getPageStats(range)`, `deletePageStats(pageId)`, `versionDoc(versionId)`) run the scoped path in store #1 (the
  converted install, a lazy `systemScope(systemCtx("legacy-admin"), LEGACY_STORE_ID)`), so today's /admin works on
  converted data until T4 moves; the maintainer deletes them once no caller is left.
- Filed by: T3 · Owner of the files: T4
- Files: `src/lib/editor/{actions.ts, pages.server.ts, preview.server.ts}`, `src/lib/admin-data/{pages.ts, dashboard.ts, time.ts}`,
  `src/app/admin/(panel)/{pages/actions.ts, settings/actions.ts, settings/pixels/actions.ts}` and their `src/app/app/[store]/**`
  successors, `src/app/api/cron/tick/route.ts`

## What

The scoped forms T3 implemented in R1.0 (the deprecated single-tenant forms stay until these callers move; their
inserts are refused by the schema's legacy shim anyway):

1. **Publish** (`src/lib/render/publish.server.ts`):
   - `publishPage(ctx.scope, pageId, { actor: ctx.actor, expectedUpdatedAt, libraryRule })`. The scoped publish does
     not call the pixel library itself (the library is per store and yours): pass
     `libraryRule: (tracking) => <your scoped enforceLibraryRule>(ctx.scope, tracking, ctx.actor)`. A `PixelError`
     `pixel_not_in_library` it throws becomes `PublishError("pixel_not_in_library")`.
   - New `PublishError` codes: `forbidden` (the store may not publish in its state, §A.5.2) and the gate codes
     `design_blocked` / `honesty_blocked` / `budget_blocked` with `error.items: GateItem[]` (§M.1: map them to the
     `ActionResult` failure with `items`). `PublishResult.notes` carries the soft items.
   - Pixels-only updates: `renderAndCommit(ctx.scope, pageId, doc, { kind: "publish", label: "Pixels only", userId,
     actor: ctx.actor, baseVersionId })`; `publishTrackingOnly` stays single-tenant until you rebuild it on that call.
   - `unpublishPage(ctx.scope, pageId, ctx.actor)` replaces `admin-data/pages.ts` `unpublishPage(id, actor)`.
2. **Slugs**: validate page slugs with `isStoreSlug(slug)` (store-reserved slugs of §C.4.1, no admin-gate check: the
   gate is a root path of the platform host, and refusing it inside a store would be an oracle for the secret).
   `isServableSlug` / `RESERVED_SLUGS` are deprecated.
3. **Render cache**: after an unpublish, a slug change, a page deletion, a home change or a store identity change,
   call `invalidateStoreRender(storeId)` (`src/lib/render/cache.server.ts`) instead of `invalidatePublished()`.
4. **Store render context** for the builder's full preview (`preview.server.ts`): `loadStoreRenderContext(scope,
   store, { pageId })`, `storeAssetResolver(scope, rc, doc)` and `storeRenderOptions(rc, { slug, pageKey, assets })`
   (`src/lib/render/store-context.server.ts`) give the store's base, origin, identity, Turnstile, scoped asset rows
   and `storePageLinks(base, slug)`; `storeInfo()`, `liveResolverFor()` (unscoped, PUB-07), `liveLinks()` and
   `publicOrigin()` are deprecated. `PUBLIC_ENDPOINTS` now lives in `store-context.server.ts` (still re-exported).
   "View live" links: `storeUrl(addressOf(store), "/<slug>")`.
5. **Stats** (`src/lib/stats/index.ts`): `getPageStats(ctx.scope, range, opts)` and `deletePageStats(ctx.scope,
   pageId)`. Store days are the store's own calendar days: build ranges with `dayKey(date, await
   storeTimeZone(scope))` instead of `STATS_TZ` (STAT-01).
6. **Private preview links** (the "Share a private preview" action): `mintPreviewToken(ctx.scope, { pageId, ttlSec,
   audience: "seller", actor: ctx.actor })` and `revokePreviewToken(ctx.scope, tokenId, ctx.actor)`
   (`src/lib/render/preview-token.ts`); refusals are `SeamError("not_found" | "forbidden")`, a bad TTL a `ZodError`.

## Why

§K.1: T4 converts the ~225 query sites and the dashboard; these are the T3 functions those sites call. The library
rule stays in your per-store pixel library rather than being re-implemented in the render module.

## Effect on others

None for the frozen contracts. The maintainer deletes the deprecated single-tenant forms at the R1.0 integration once
no caller is left.
