# r1.0-t3-4: a `health` window in the burst limiter for `GET /api/health`

- Status: open
- Filed by: T3 · Owner of the file: maintainer (no R1.0 track owns `src/lib/security/burst-limit.ts`, C0a report §7.8)
- Files: `src/lib/security/burst-limit.ts`, then `src/app/api/health/route.ts` (T3, one line)

## What

1. `src/lib/security/burst-limit.ts`, `BURST_LIMITS`:

   ```diff
      cron: { limit: 30, windowSec: 600 },
   +  /** public liveness (GET /api/health): monitors poll every minute or so; one `SELECT 1` per allowed call */
   +  health: { limit: 60, windowSec: 60 },
    } as const;
   ```

2. After it is applied, T3 changes `burstLimit("event", …)` to `burstLimit("health", …)` in
   `src/app/api/health/route.ts`.

## Why

§H.5: `GET /api/health` is public and "burst-limited". The limiter has no scope for it, so the R1.0 route uses the
`event` window (240 per minute per network), which is far above any monitor and shares its budget with the
analytics beacons of the same network. A scope of its own keeps the two apart and caps the database probes a
single network can cause at one per second.

## Effect on others

None. The `event` window keeps its budget for beacons.
