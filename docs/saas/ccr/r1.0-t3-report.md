### `edge/worker.js` (§C.5)

The Worker follows the contract's pseudo-code, including `cf: { cacheTtl: 0, cacheEverything: false }` (ENGC-2),
`redirect: "manual"`, the six `x-sg-*` stamps, and the deletion of `Set-Cookie` and `Cookie`.

Additions, all fail-closed:

- **Bad bindings.** A missing or short `EDGE_KEY`, or an `ORIGIN` that is not a bare `https://` origin, gets a 503
  from the Worker itself, with no subrequest.
- **Refused paths.** The path is decoded before the refusal test (`/%61dmin`, `//admin`), like the app's `areaOf`.
- **The apex and `www`** are refused with a 404. They should never run the Worker; this is where `STORE_ROOT` is used.
- **Dropped request headers.** Besides `x-sg-*` and `Cookie`, the Worker drops `Host`, `x-middleware-*`, `x-invoke-*`,
  `x-next-*`, `x-nonce`, `x-cs-pathname`, `x-forwarded-host`, `forwarded` and `x-real-ip`.
- **`WORKER_VERSION`** is validated, and sent as `unset` otherwise.
- **An unreachable origin** gets a neutral 503 instead of Cloudflare's error page.

The header comment carries the EDGE_KEY rotation runbook (§C.5). The Worker keeps no state.

### `qa:edge-sim` and `qa:headers`

Both scripts have an offline part and an online part. The offline part always runs. The online part runs with
`--base http://127.0.0.1:3451` against a production build, and refuses a server whose `/api/health` is not Store Gen
(QA-01). Neither script prints a secret.

`npm run qa:edge-sim`: **132 checks**. It runs the real `edge/worker.js`, then a model of Cloudflare's cache (keyed
by the subrequest URL, worst-case zone "Cache Everything"), then the real `src/proxy.ts`, then the real
`documentResponse` and `permanentRedirect`. It covers:

- the Worker alone: bindings, refusals, stamping, the raw path and query, the `cf` option, `Set-Cookie`, the 503s;
- S-mode rewrites, including the home without a trailing slash (ENGC-15);
- no Cookie reaching a store route or a public API (SEC-2);
- the signed path and the re-verified edge as the handler sees them (SEC-3, D18);
- the own-handle 308, and an open-redirect probe of it;
- store-host refusals at the proxy, with the Worker's own list bypassed;
- a wrong key (SEC-4), the 3-step EDGE_KEY rotation, and a header set replayed after 6 minutes;
- the document CSP naming only the store host;
- the cache: with the `cf` option, with a zone rule that ignores it, and a **negative control that must leak**;
- `__Host-` platform cookies (SEC-13);
- a client `x-sg-path` outside the matcher.

A mutation test confirmed that the suite fails when the Worker keeps `Set-Cookie` or forwards `x-forwarded-host`, or
when the 308 loses its `CDN-Cache-Control`.

The online part (§J.3): store home 200, `/x/` ≡ `/x`, own-handle 308, store-host 404s and `Next-Action`, the
wrong-key 404, no `Set-Cookie` from the app on store hosts, `__Host-` on the platform, CSP per host, the apex not
serving a store's page, and the forged path on the upload route.

`npm run qa:headers`: **677 checks**. The §F.6 matrix in P mode and S mode:

- **The neutral set.** One header set per host class across:
  - the proxy: un-gated console, `/d`, legacy refusals, store-host refusals, reserved labels, a wrong key, a foreign host;
  - the route producers: 404, 410, 503 + `Retry-After`, and the `Origin: null` action 403.
  - It also checks the set's §F.6 content and the body per method.
- **Platform UI.** Per area: the nonce (fresh per request), `same-origin` versus `/kit/*` `no-referrer`, marketing
  being cacheable, the gated console, and the manifest without nonce headers or a cookie.
- **HSTS per host class.** `includeSubDomains` only on the platform in S mode.
- **Redirects.** Every proxy redirect, the canonical 308, and the canonical 308 via the edge.
- **Store documents.** Every kind on the platform host in P and S mode, and on the store host: cache policy,
  robots, referrer, COOP / CORP, `CDN-Cache-Control` only via the edge, HSTS, and the narrowed CSP. Neither a host
  outside `storeHosts` nor a reflected `Host` / `X-Forwarded-Host` ever reaches the CSP.
- **`apiHeaders`.**

The online part repeats these over HTTP, adding the fallback rewrite, `/api/health`, and the media route
(`--media`). The `/go/<code>` 308 (`--go`) is checked once P3's short links exist.

## 5. Security self-review (step 4) and fixes

- **Host / X-Forwarded-Host trust.**
  - The Worker's `x-sg-host` and `x-sg-ip` are used only when `x-sg-edge` verifies (constant-time sha256 digests,
    `x-sg-ts` within 5 minutes).
  - The proxy deletes every client `x-sg-*`, and handlers re-verify the edge themselves (D18).
  - Store-document CSPs never reflect `Host` or `X-Forwarded-Host` in production. The store host enters a CSP only
    when it came via the edge and is in `storeHosts(store)` (asserted in `qa:headers`).
  - The Worker now drops client `x-forwarded-host` and `forwarded` as well.
  - **Residual, outside T3:** `requestHost()` (`src/lib/auth/gate.ts`, T2) falls back to the right-most
    `X-Forwarded-Host` when `Host` is internal. If Hostinger's front proxy ever replaced `Host` and passed a client
    XFH through untouched, a direct client could pick the platform, legacy or console class. It could never pick a
    store class, which needs the key, and the strict CSRF check still needs a same-origin `Origin`. Worth a line in
    T2's review; no CCR, since the behaviour is unchanged from C0a.
- **Open redirects in 308s.**
  - The proxy builds every `Location` by assigning a path to a configured origin. `//evil.example/x` stays on the
    host; this is tested on legacy hosts and on the own-handle 308.
  - Store-route 308s are absolute `storeUrl()` values or a store-base path built from a validated stored slug.
  - The Worker never follows redirects (`manual`).
- **Header injection.** Every value the proxy and the Worker set comes from a normalized host, a validated version
  (`^[A-Za-z0-9._-]{1,64}$`), a URL-encoded path, or a digit timestamp. The Headers API refuses CR / LF anyway.
  Nothing logs request headers (checked by grep).
- **CSP correctness per host class.**
  - Platform UI: nonce + `strict-dynamic`.
  - Neutral pages: `default-src 'none'` with the one style hash.
  - Store documents: `connect-src` / `form-action` narrowed to `<serving origin>/api/public/`, never a bare `'self'`
    (SEC-2), with `img-src` allowing the platform origin for media on store hosts.
  - Media: a sandbox CSP.
  - All of this is asserted by `qa:headers` and `qa:edge-sim`.
- **Cookie scope.** Every platform cookie is `__Host-` (Secure, `Path=/`, no `Domain`; asserted). Store hosts:
  `Cookie` is deleted by the Worker and by the proxy, and `Set-Cookie` is stripped by the Worker. The app sets none
  there (asserted offline, and online at the integration).

**Fixed in step 4:**
1. **Canonical 308s served via the edge** (renamed handle, upper-case slug) now carry `CDN-Cache-Control: no-store`
   (`permanentRedirect`, `src/lib/render/serve.server.ts`).
   - The problem: their `public, max-age=300` under the apex cache key would have sent other stores' visitors of
     that path to this store (ENGC-2, applied to redirects).
   - `qa:edge-sim` proves the fix, and fails without it.
2. **The media route sends HSTS** of the request's host class in production (§F.6 media row). `/media/*` never
   passes the proxy, so it had none.
3. **The Worker's hardening** listed in §1.

**Found, not fixable in T3:** `console.<domain>` through the Worker would break sign-in (CCR r1.0-t3-8). The `cf`
option's cache semantics need a live V3 check (CCR r1.0-t3-9).
