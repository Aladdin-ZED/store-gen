# r1-p8-19: a `test:tenancy` case for the render queue (enqueueRenders, renderSummary)

- Status: **open, for the P8 merge** (the code it calls is real from P8 step 5).
- Filed by: P8 · Owner of the file: maintainer (`scripts/qa/tenancy-check.ts`) · Spec: §F.1 attack list, §H.3, D25
- Files: `scripts/qa/tenancy-check.ts`

## What

Add one case to `specialCases`. It runs with the harness's own helpers (`call` with each role of B, `snapshot` of A,
`leaks`):

```ts
// B's scope enqueues A's page id → nothing queued, A's rows unchanged; renderSummary(B) names nothing of A (§H.3, D25)
{
  const { pool } = load<typeof import("@/lib/db/client")>("@/lib/db/client");
  const RQ = load<typeof import("@/lib/jobs/renders")>("@/lib/jobs/renders");
  const S = load<typeof import("@/lib/tenancy/seam")>("@/lib/tenancy/seam");
  const pageA = fx.A.pages[0]!.id; // a live page of A
  const snapA = await snapshot(fx.A.id);
  for (const role of ["owner", "admin", "editor"] as const) {
    const r = await call({ userId: fx.B.members[role] }, appPath(fx.B.handle, "/settings/general"), async () =>
      RQ.enqueueRenders(S.memberWriteScope(await S.requireStoreMember()), [pageA], "store_info"),
    );
    check(`enqueueRenders as B's ${role} with A's page id → enqueued 0`, r.kind === "ok" && (r.value as { enqueued: number }).enqueued === 0, r);
    const sum = await call({ userId: fx.B.members[role] }, appPath(fx.B.handle, "/"), async () => RQ.renderSummary((await S.requireStoreMember()).scope));
    check(`renderSummary as B's ${role}: no page or job of A`, sum.kind === "ok" && !JSON.stringify(sum.value).includes(pageA) && leaks(sum.value).length === 0, sum);
  }
  const [rows] = (await pool().query("SELECT COUNT(*) AS n FROM render_jobs WHERE page_id = ?", [pageA])) as unknown as [{ n: number }[]];
  check("no render job of A's page was created from B", Number(rows[0]!.n) === 0, rows);
  check("A's rows unchanged", (await snapshot(fx.A.id)).hash === snapA.hash, snapshotDiff(snapA, await snapshot(fx.A.id)));
}
```

The fixture names (`fx.A.pages`, `members[role]`) and the `Outcome` fields are the harness's. Adapt them to its
helpers as written at the merge. `snapshot()` must include `render_jobs`, a tenant table since 0005.

## Why

§F.1 wants every store-facing read and write in the two-store suite. P8 has no case file of its own (§K.2 gives P8 no
`tenancy-cases/<track>.ts`). P8's DB suite already proves the rule on the library (`test:storage`, section `renders`):

- B's page id under A's scope inserts nothing and is counted;
- B's scope claims none of A's jobs and cannot write A's outcome;
- `renderSummary(A)` and `renderSummary(B)` name nothing of the other store.

This CCR adds the same proof to the attack suite.

## Effect on others

None. The callers that enqueue (P3, P4, P5, P6, the media pipeline) keep their own action cases. This case covers the
library path they share.
