## What

`docs/DESIGN.md` v3 is written (C0b step 3). Writing it against the DES-§3 content contract found seven places where the
spec contradicts itself, the core or the frozen runtime. v3 takes a decision on each (below) so build agents read one
rule; the spec text should follow so P6 implements the same thing.

### 1. The colour-word check needs word boundaries (DES-§3.5, DES-§1.1 and §1.4 DG-01 rows)

`rust` matches "trust": the "Trust strip · countdown" row of the verbatim budgets table, `trustBar`, "trusted by". With
the grep as written, 9 lines of v3 outside §0 hit, all of them "trust", so "hits §0 only" can never hold.

```diff
-grep -inE "amber|terracotta|saffron|tomato|coral|ochre|apricot|peach|copper|rust|tangerine" docs/DESIGN.md
+grep -inwE "amber|terracotta|saffron|tomato|coral|ochre|apricot|peach|copper|rust|tangerine" docs/DESIGN.md
```

The same `-w` in the shorter list of the DES-§1.1 DG-01 row; in `theme:check` the regex is
`/\b(amber|terracotta|saffron|tomato|coral|ochre|apricot|peach|copper|rust|tangerine)\b/i`. Measured on v3: the
word-bounded grep hits lines 69, 109, 110 and 114, all inside §0.

### 2. One budget row carries a forbidden word (DES-§3.2)

"Verbatim" and "hits §0 only" cannot both hold while the row label reads "Gold / amber band". v3 §1.1 writes the row as
"Gold band"; the rest of the table is byte-identical to DES-§3.2 (checked with `diff` at C0b: one line differs).

```diff
-| Gold / amber band (rev 3, UX-17) | hue 75-95° at chroma > 0.10 never on the `accent` or `pop` role (hard); …
+| Gold band (rev 3, UX-17) | hue 75-95° at chroma > 0.10 never on the `accent` or `pop` role (hard); …
```

After this change the DG-01 string compare (DES-§1.4) passes on the 37 lines of the table.

### 3. `data-reveal` on `<html>` collides with the frozen runtime (DES-§4.5.2, DES-§4.2 G23 row)

DES-§4.5.2 adds `data-reveal` (the space-separated reveal kinds) to `<html>`. The frozen runtime selects every
`[data-reveal]` element of the document (`src/landing/runtime/reveal.ts:16, 27, 77`: `$$(c.doc, SEL)` is
`document.querySelectorAll`, `core.ts:111-112`, which matches the root element too): it would observe `<html>` and flag
it `data-in`, and every reveal-node count (R5, V28, `budget:R5`) would count it. v3 §2.5 names the attribute **`data-reveal-kinds`** (same values, a token list of 1-2).

```diff
 DES-§4.5.2: new attributes are added: `data-look="1"`, `data-grammar`, `data-ladder`, `data-depth`, `data-labels`,
-`data-align`, `data-img`, `data-reveal` (space-separated reveal kinds), `data-numbering`, `data-caption`, `data-corner`;
+`data-align`, `data-img`, `data-reveal-kinds` (space-separated reveal kinds; not `data-reveal`, which the frozen
+runtime selects on every element), `data-reveal-scope`, `data-numbering`, `data-caption`, `data-corner`;
 DES-§4.2 G23 row, "Compiles to":
-`--lp-ease*`, `--lp-dur-*`, `--lp-stagger`, `data-reveal`, the hero choreography row (DES-§4.12)
+`--lp-ease*`, `--lp-dur-*`, `--lp-stagger`, `data-reveal-kinds`, the hero choreography row (DES-§4.12)
```

### 5. The `glow` stage preset exceeds the core's glow ceiling (DES-§4.11.1)

Core D60 (rev 5) and the Glow row of DES-§3.2 allow one product-tinted radial at **≤ 10 % alpha** ("the stage glow
behind a cutout, `GlowOrb`"); the `glow` row of DES-§4.11.1 (rev 3) emits 0.28 (light) / 0.22 (tinted) / 0.38 (dark)
and 0.12 for the second radial. v3 §6.5 decides: the four values are scaled by 0.10 / 0.38 (the dark value lands on the
ceiling, the others keep their proportion).

```diff
-`color-mix(in oklch, product dominant 70%, ground)` at alpha **0.28** on light (L ≥ 0.8), 0.22 tinted, **0.38** dark;
-a second, tighter radial (`0.45 w`) at alpha 0.12 for depth
+`color-mix(in oklch, product dominant 70%, ground)` at alpha **0.074** on light (L ≥ 0.8), 0.058 tinted, **0.10** dark
+(the core D60 ceiling); a second, tighter radial (`0.45 w`) at alpha 0.032 for depth
```

### 6. The bold-gene sampling order (DES-§4.2 vs DES-§4.4)

table: G23.f "sampled 6th", G28 "sampled 7th".

## Notes (no change asked)

- **`data-texture`.** v3 §2.5 keeps `none | grain` because `TEXTURE_KINDS` still holds `grain` and `ThemeSpec.texture`
  validates it on old documents; the engine emits only `none` from P6 (DS4 rev 6). If P6 narrows the set, the §2.5 line
  changes with it in the same commit.
- **§2.5 is parseable today.** One attribute per line, values separated by ` | `, nothing else in the block. A scratch
  parse at C0b compared it with `THEME_ATTR_VALUES` and the frozen `ThemeLook` enums of `src/lib/page/schema.ts`: every
  existing set is equal except the DES-§4.5.2 additions (`data-emphasis` + `none`, `data-mask` + `rect`, `cut`), and
  every look-only set equals its `ThemeLook` enum.
- **v2 section numbers in comments.** About 30 files cite `DESIGN.md §n` with v2 numbers (`src/lib/theme/*`,
  `src/landing/**`, `src/lib/generator/*`, `scripts/check-theme.ts`, `scripts/build-landing-assets.mjs`,
  `docs/SECTIONS.md`, `docs/ARCHITECTURE.md`). v3 opens with a "Where v2 sections went" map, so nothing breaks; owners
  may update the numbers when they next touch a file.

## Why

DG-01 acceptance (DES-§1.1, §1.4) asks for three mechanical checks on `docs/DESIGN.md`; items 1-2 make two of them
satisfiable together, items 3-4 keep the bible's §2.5 (which `THEME_ATTR_VALUES` follows) clear of the frozen runtime,
and items 5-6 remove the two numeric contradictions a P6 build agent would otherwise resolve on its own.
