## 2. Sign-up asks for the documents in the spec's locale order (T2, `src/lib/auth/signup.ts`)

### Why

PLA-§13.4: sign-up and staff invites ask for the published `tos`, `privacy` and `aup` "in the user's locale, falling
back in the order locale → fr → en → ar". T2's `currentLegalDocuments(locale)` falls back locale → en → any. With only
a French ToS and an Arabic Privacy published, an English signup gets the same answer either way, but an Arabic signup
with only French and English versions accepts the English one where the spec says French. Staff invites already use
P1's order (`acceptanceDocsFor`), so the two paths can disagree.

### What

```diff
+import { acceptanceDocsFor } from "@/lib/platform/legal";
@@
-async function currentLegalDocuments(locale: AccountLocale): Promise<{ id: string; kind: string }[]> {
-  const rows = await db.select(…).from(legalDocuments).where(…);
-  …
-  return [...best].map(([kind, v]) => ({ id: v.id, kind }));
-}
+/** The published ToS, Privacy and AUP the person accepts (PLA-§13.4: locale → fr → en → ar; a kind with none is not asked). */
+const currentLegalDocuments = (locale: AccountLocale) => acceptanceDocsFor(locale);
```

`acceptanceDocsFor(locale): Promise<{ id: string; kind: "tos" | "privacy" | "aup" }[]>` is exported from
`src/lib/platform/legal.ts` (server-only, no import from `src/lib/auth/**`, so no cycle). Nothing else changes: the
acceptance rows keep `context = 'signup'` and the new store's id.

### Proof

`test:platform-db -- --case 8` signs up through `signupAccount` with no published ToS (only the published Privacy is
accepted) and after a new Privacy version (the newest version is accepted, nobody is asked again). After the change,
add an Arabic signup with French and English versions published: the French one is accepted.

## 3. The kill-switch banners in P2's catalog (P2, `shell.ts` × 3)

### Why

PLA-§12.1: the toggle sheet previews "the exact `shell.kill.<key>` texts" in ar / fr / en, and the tenant banner
renders the same keys (PLA-§N.3). They are P2's keys and not on `r1/p1`. `killSwitchPreview()` reads them through
`messageOf("shell.kill.<key>", locale)` and, while a key is missing, shows the reference text below and sets
`bannerFallback: true` (the sheet says so). The texts of `publishing_enabled` and `platform_read_only` are PLA-§N.3's;
the others follow its pattern (what is paused, and that orders keep working).

### What

P2's `src/lib/i18n/admin/<l>/shell.ts` carries, in ar / fr / en, `shell.kill.signups_enabled`,
`shell.kill.publishing_enabled`, `shell.kill.ai_generation_enabled`, `shell.kill.sheets_sync_enabled`,
`shell.kill.capi_enabled`, `shell.kill.uploads_enabled`, `shell.kill.platform_read_only`. The reference texts are
`KILL_BANNER_FALLBACK` in `src/lib/platform/flag-rules.ts` (P2 may reword them; the preview follows the catalog).

### Proof

`test:platform` checks every switch has a banner in the three locales; once the keys exist, `bannerFallback` reads false
for every key (the step-13 e2e proves the banner a seeded store shows within 45 s is the previewed text).

## 4. Slot 9 lists `platform.rerender` (maintainer, core §H.2)

### Why

PLA-§16.2: "Re-render all live pages" calls P8's `enqueueRenders` per store "through a fan-out job so the request
returns at once". The request only writes its state row (`cron_cursors` key `platform.rerender:request`, counts and
ids), and the new `platform.rerender` job of P1's `src/lib/jobs/tracks/platform.ts` walks the serving stores in slices
of 50 until its deadline. Idle, it is one primary-key read. §H.2's slot 9 row names the four platform jobs of the
spec and not this one.

### What

§H.2, slot 9 row: "… `platform.entitlements` (hourly: expired boosts and overrides), **`platform.rerender` (tick,
≤ 0.5 s: the Domains view's re-render fan-out, idle in one read; PLA-§16.2)**". The slot's budget is unchanged: the
jobs share its 3 s guaranteed + up to 6 s of leftover.

### Proof

`test:platform-db -- --case 19`: the request returns with nothing enqueued, a second request while it runs starts
nothing, the job runs the fan-out (or stops as `unavailable` while P8's `enqueueRenders` is the stub, never a made-up
count).
