# r1.0-m-2: admin/owner invites take the tenant step-up; /app/new follows the signup mode

- Status: open (the code half applied in "R1.0: T2 AUTH review fixes"; the spec half waits for its owner)
- Filed by: maintainer (T2 review F1, F4) · Owners: core spec (`docs/STORE-SAAS.md` §B.7, PD80), platform spec (`docs/saas/spec/platform.md` PLA-§3.1), P2 (team sheet)
- Files: `docs/STORE-SAAS.md` (§B.7 tenant ladder, PD80), `docs/saas/spec/platform.md` (PLA-§3.1 mode table)

## What

1. **§B.7 / PD80 (applied in code):** the tenant step-up ladder lists "an invite for `admin` or `owner`" next to the
   role change to `admin` / `owner`. `createInvite` calls `assertStepUp(ctx)` for those roles before anything is
   written, and `store.member.invited` carries `meta.stepUp` (`totp` | `password`) like `store.member.role_changed`.
   T2's team sheet already sends the invite through the step-up sheet (`useStepUp().guard`); P2's team screen keeps
   that when it replaces the sheet.
2. **PLA-§3.1 (applied in code):** `/app/new` (`createAdditionalStore`) answers `closed` in `closed` and `waitlist`
   modes. In `invite` mode only an account that already holds an active `owner` membership may open another store
   there; any other account needs a platform code, which only the signup form takes. The mode table gains a
   "`/app/new`" column: open / approval: any account; invite: existing owners; waitlist / closed: nobody.

## Why

- F1: with a stolen session cookie an owner could invite the attacker as `owner` without any proof, and that
  membership outlives a password change or "sign out other devices". The role change already asked for the step-up;
  removing a member and re-inviting them was the same escalation without it.
- F4: accounts made through a store invite never needed a platform code, so in invite / closed / waitlist mode they
  could still open pending sandboxes (3 a day each) and use up the D69 daily `pending_stores` ceiling.

## Effect on others

- P2: the team screen handles `step_up` on `createInviteAction` (open the step-up sheet, send again).
- If the owner wants every existing account (not only owners) exempt in invite mode, change `ownsAStore` in
  `src/lib/auth/signup.ts` and the PLA-§3.1 column together.
- Tests: `selftest-team` (invite step-up, the audited method, the action's `step_up`), `selftest-identity` (`/app/new`
  per mode).
