## What

The identity functions of T2 (src/lib/auth/**, src/lib/tenancy/invites.ts, src/lib/tenancy/seam.ts) answer these
action codes and message keys (`ActionResult.error` / `.message`, `FieldsError` items). D65: every part code needs
`error.<code>` in ar / fr / en, and the shell renders an unknown key as the key itself. Add them to the base catalogs
(or, from P0, to the extension files named above). No em-dash, no "Step n" label (§I.8 rule 8).

### Notification kinds (P0 registry, PLA-§18.2)

`notify()` is called with three kinds the registry does not declare yet: `user.2fa_reset` (tenant, security group,
warn, link `/app/account/two-factor`), `user.password_reset` (tenant, security, warn, link `/app/account/security`;
both PLA-§11.2) and `staff.signup_capped` (platform staff, `minRole: "admin"`, vars `{ day }`, dedupe
`signup_capped:<day>`, PLA-§3.1). Tenant kinds need `notify.<kind>.title` / `.body` in ar / fr / en.

## Why

D65 and §I.5: a code without its three texts renders as a raw key; the R1 surfaces `/login`, `/signup`, `/invite` and
`/reset` are R1-complete in ar / fr / en.

## Effect on others

None. Keys only; P0 moves them into the owners' extension files without renames.
