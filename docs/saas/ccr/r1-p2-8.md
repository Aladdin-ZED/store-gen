## 1. The inviter's first name on `/invite/<token>` (PLA-§22.1.4)

The card should read "<Inviter first name> invited you to join as **Agent**" (`team.invite.invited_by`, already in
ar / fr / en). `InvitePreview` has no inviter field, so the page shows the role and its one-line explainer only.

```ts
// src/lib/tenancy/invites.ts
export interface InvitePreview {
  storeName: string;
  storeLogoKey: string | null;
  role: StoreRole;
  emailMasked: string;
  /** the inviter's first name (first word of users.name, ≤ 40 chars), never the e-mail */
  inviterFirstName: string | null;
}
```

`previewInvite` / `inviteLanding` join `users` on `store_invites.invited_by` (the row is already read for the
`invitableRoles` check at acceptance). Once present, the page renders `t("team.invite.invited_by", { name, role })`
above the role line.

## 2. The legal acceptance of an account created through an invitation (PLA-§22.1.4 table, row 3)

The sign-up variant of `/invite/<token>` now shows the legal checkbox when `platform.legal.requireAcceptance` is on,
and `acceptInviteAction` refuses a missing tick with `auth.signup.legal_required` before `acceptInvite()`. The
acceptance itself is not recorded: `NewAccountInput` has no `acceptLegal`, and only `signupAccount` writes
`legal_acceptances`. Ask: `NewAccountInput.acceptLegal?: boolean`, and `acceptInviteTx` inserts the same
`legal_acceptances` rows as signup step 7 (the published tos / privacy / aup versions in the account's locale, with
the fallback order of `publishedPlatformDoc`) inside its transaction when it is true.

## 3. The locale cookie's HttpOnly flag (PLA-§22.1, PD71, SEC-13)

`localeCookieOptions()` (src/lib/auth/locale.ts) sets `httpOnly: true`; PLA-§22.1 says the `__Host-sgl` cookie is not
HttpOnly (a display preference the switcher may read client-side). The P2 switcher never reads it client-side (it
posts `setLocaleAction` and refreshes), so nothing breaks; the spec and the code disagree. Ask: either drop
`httpOnly` to match the spec, or amend PLA-§22.1 to "HttpOnly (the switcher posts a server action)". P2 has no
preference.
