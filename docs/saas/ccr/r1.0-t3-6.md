# r1.0-t3-6: store setting writes that change public documents drop the store's render cache

- Status: open
- Filed by: T3 · Owner of the file: T1
- Files: `src/lib/settings/index.ts`

## What

In `setStoreSetting` / `updateStoreSetting`, after a successful write of one of the keys the public documents read
(`store`, `brand`, `policies`, `turnstile`, `conversions`), call

```ts
import { invalidateStoreRender } from "@/lib/render/cache.server";
// …
if (RENDER_KEYS.has(key)) invalidateStoreRender(scope.storeId);   // RENDER_KEYS = new Set(["store", "brand", "policies", "turnstile", "conversions"])
```

(`invalidateStore(storeId)` does it too, if the write path already calls that.)

## Why

The store's legal pages (`/s/<h>/policies/<kind>`) and its "no page yet" home are rendered on request from the
store's current facts and cached per store for 60 s (`src/lib/render/store-pages.server.ts`, `scopedCache("render")`).
Without the call, a seller who completes the store details sees the old legal text for up to a minute. Published
landing pages are not affected (they keep the bytes of their publish; a brand or contact change re-renders them
through the render queue, §H.3).

The render context reads, through T1's API: `getStoreSettings(scope, ["store", "brand", "turnstile",
"conversions"])` and, when the store has no Turnstile keys of its own, `getPlatformSetting("platform_turnstile")`
(`src/lib/render/store-context.server.ts`).

## Effect on others

None. `cache.server.ts` imports nothing but the scoped cache, so the import adds no cycle.
