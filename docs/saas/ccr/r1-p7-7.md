# r1-p7-7: a seam narrowing for runAi's write scope (lint L6)

- Status: open
- Filed by: P7 (step 7) · Owners: maintainer (src/lib/tenancy/seam.ts, core §K.3)
- Files: src/lib/tenancy/seam.ts (maintainer), src/lib/ai/router/write-scope.ts and its five importers (P7, at the merge)

## What

`runAi(scope: StoreScope, …)` is frozen at P0 with a `StoreScope` (src/lib/contracts/r1-p0.ts), but a server run writes
the store's `ai_runs`, `ai_cache` and `store_usage` rows, and those repositories take a `WriteScope` (D71). The router
must narrow the scope it was given: the writable kinds (`member`, `public`, `system`) run, an `impersonation` or a
`platform` scope answers `state` before any read. Lint L6 allows that narrowing only in src/lib/tenancy/seam.ts, so
step 7 keeps it in one local function (`writeScopeOf` in run.server.ts) and reports exactly one L6 `cast` until this
CCR lands.

Add to src/lib/tenancy/seam.ts, after `memberWriteCtx`:

```ts
/**
 * The write scope of a scope the seam minted writable (member, public, system), or null for a read-only one
 * (impersonation, platform). For the frozen entry points that take a StoreScope and write the store's own rows
 * (P7 `runAi`, CCR r1-p7-7); a caller treats null as `state`.
 */
export function writeScopeOf(scope: StoreScope): WriteScope | null {
  return scope.kind === "member" || scope.kind === "public" || scope.kind === "system" ? (scope as WriteScope) : null;
}
```

Then delete src/lib/ai/router/write-scope.ts (step 8 moved the local `writeScopeOf` there from run.server.ts, so the
job drivers, the batch queue and `queueAi` share it without importing the provider) and point its importers at the
seam: `import { writeScopeOf } from "@/lib/tenancy/seam";` in src/lib/ai/router/run.server.ts (which re-exports it),
src/lib/ai/router/server.ts, src/lib/ai/jobs/claim.ts, src/lib/ai/jobs/enqueue.ts and src/lib/jobs/tracks/ai.ts. No
other caller changes: the lint goes back to 0.

## Why

The frozen signature cannot change, the repositories must stay `WriteScope`-typed, and the cast belongs in the seam
(§E.1, D71). Nothing else in step 7 needs the allow file: the provider's process state (client, breaker, semaphores,
class marks, fast cooling) lives in a `scopedCache` under the platform id "p" (src/lib/ai/server/process.ts).
