# r1.0-t3-1: the console's redirect-back path reads the signed `x-sg-path`, not `x-cs-pathname`

- Status: applied in fa880e4 (T3 merge; T2 merged, its files are the maintainer's). Item 1: `getRequestedAdminPath()` reads
  `verifiedRequestPath(headers)` (the signed `x-sg-path`). Item 2: `ADMIN_PATH_HEADER` is removed from
  `src/lib/auth/config.ts`; the proxy no longer stamps `x-cs-pathname` and still deletes a client copy (a local
  `LEGACY_PATH_HEADER`); the legacy-admin entry check of `src/lib/auth/index.ts`, its other reader, now asks whether the
  signed path is in the console area (`areaOf`). `test:hosts` asserts the header is never re-stamped.
- Filed by: T3 · Owner of the file: T2
- Files: `src/lib/auth/request.ts`, `src/lib/auth/config.ts`

## What

1. `src/lib/auth/request.ts`, `getRequestedAdminPath()`: read the path from the proxy-signed request path
   instead of `ADMIN_PATH_HEADER`:

   ```diff
   -import { ADMIN_PATH_HEADER, GATE_COOKIE, NONCE_HEADER } from "./config";
   +import { verifiedRequestPath } from "@/lib/edge/path-sig";
   +import { GATE_COOKIE, NONCE_HEADER } from "./config";
   …
    export async function getRequestedAdminPath(): Promise<string | null> {
   -  return safeAdminPath((await headers()).get(ADMIN_PATH_HEADER));
   +  return safeAdminPath(verifiedRequestPath(await headers()));
    }
   ```

2. `src/lib/auth/config.ts`: keep exporting `ADMIN_PATH_HEADER` (marked `@deprecated`) until T3 drops its last
   use in `src/proxy.ts`. Remove it after that (T3 tells T2, or the maintainer removes it at the R1.0
   integration).

## Why

§C.3 step 2: `x-sg-path` (pathname + search, ≤ 512 chars, on every request, signed with `x-sg-rid` and
`x-sg-path-sig`) **replaces** `ADMIN_PATH_HEADER` `x-cs-pathname`. Until this is applied, T3's proxy keeps stamping
`x-cs-pathname` on console requests, and only there (`src/proxy.ts`, `platformUi()`), so the console's
post-login redirect keeps working. It still deletes every client-sent copy of the header.

`verifiedRequestPath()` returns the path only when its signature verifies. A handler outside the proxy matcher
therefore never redirects to a client-chosen value. `safeAdminPath()` still applies on top.

## Effect on others

- After it is applied, T3 removes the `x-cs-pathname` stamping and the `ADMIN_PATH_HEADER` import from
  `src/proxy.ts` (one line each) and `test:hosts` drops its `x-cs-pathname` case.
- None for other tracks or the frozen contracts.
