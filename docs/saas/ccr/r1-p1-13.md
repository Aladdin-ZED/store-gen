## 1. `listPlatformAudit`: `userId`, `from`, `to` (maintainer, core `src/lib/audit.ts`)

**Why.** `/admin/security/audit` (PLA-§14.3) filters by store, staff member, actor kind, action prefix and a date range.
`listPlatformAudit(ctx, opts)` filters store, actor kind and area in SQL but has no `userId` and no date bounds (its
tenant twin `listStoreAudit` got `actorKind`, `from` and `to` at P0b, CCR P2-12). P1's `listAuditPage`
(`src/lib/platform/audit-log.ts`) applies the staff and date filters over the scanned rows instead: newest first, at
most 3,000 rows per page request, stopping early once a row is older than `from`; when the bound is reached before 50
rows match, the page says so and "Older" continues the scan. Correct, but a rare staff member over a long log needs
several clicks.

**What.** The same shape as `listStoreAudit`'s P0b addition:

```diff
 export async function listPlatformAudit(
   ctx: PlatformCtx,
-  opts: { storeId?: string; actorKind?: string; beforeId?: number; limit?: number; area?: string } = {},
+  opts: { storeId?: string; actorKind?: string; beforeId?: number; limit?: number; area?: string; userId?: string; from?: Date; to?: Date } = {},
 ): Promise<AuditEntry[]> {
   …
+  if (opts.userId !== undefined) {
+    if (!/^[0-9A-Z]{26}$/.test(opts.userId)) return [];
+    filters.push(eq(auditLog.userId, opts.userId));
+  }
+  const badDate = (d: Date | undefined) => d !== undefined && !(d instanceof Date && Number.isFinite(d.getTime()));
+  if (badDate(opts.from) || badDate(opts.to)) return [];
+  if (opts.from !== undefined) filters.push(gte(auditLog.createdAt, opts.from));
+  if (opts.to !== undefined) filters.push(lt(auditLog.createdAt, opts.to));
```

After it lands, P1 passes the three filters through in `listAuditPage` and drops the in-memory pass (one line each).

## 2. `PlatformHealth.outbox.dead` (P8)

**Why.** PLA-§15.1's Queues panel lists the dead outbox items (store, kind, topic, attempts, last error) with
**Replay** (`stores.lifecycle`, P8 `replay(ctx, id)`). The frozen `PlatformHealth.outbox` carries the counts by kind and
state and the oldest pending per store, but no dead item ids, so the panel shows the dead counts and points to the
store profile's Overview strip 4, where `replayOutboxAction` already replays one item.

**What.** An optional field, so the frozen readers keep compiling:

```diff
   outbox: {
     byKind: { kind: OutboxKind; state: OutboxState; count: number }[];
     oldestPending: { storeId: string | null; kind: OutboxKind; at: string }[];
+    /** the newest 20 dead items platform-wide (PLA-§15.1 Replay) */
+    dead?: { id: string; storeId: string | null; kind: OutboxKind; topic: string; attempts: number; lastError: string | null; at: string }[];
   };
```

P1 then adds the list with Replay to `src/components/console/health/panels.tsx` (`Queues`), calling the existing
`replayOutboxAction({ storeId, id })` per row.
