## What

1. `scripts/qa/tenancy-allow.json` (L4: module-scope `globalThis.__cod*` state or `new Map(` / `new Set(` in
   `src/lib/**` outside `scopedCache()`). One entry per process-wide state of T4's files, each keyed per store, per
   store-owned id or per platform-level value, never shared between stores:

   | file | symbol | reason |
   |---|---|---|
   | `src/lib/media/store.ts` | `__codMediaState` | media byte LRU and disk-miss set keyed by the global media key (D28); a key names one store's asset (per-store ids, MED-01) |
   | `src/lib/media/files.ts` | `__codMediaState` (reads `misses`) | the same state as `store.ts` |
   | `src/lib/media/ensure-focus.ts` | `__codFocusFlights`, `__codFocusMisses` | one in-flight subject analysis per asset id (per store, MED-15) |
   | `src/lib/media/gate.ts` | `__codMediaGate` | process-wide upload concurrency with the per-store share (`stores` keyed by store id) |
   | `src/lib/media/upload-slots.ts` | `__codUploadSlots` | upload slots per process, per store id and per user id |
   | `src/lib/media/throttle.ts` | `__codMediaThrottle` | the public media route's byte throttle per client IP (platform level) |
   | `src/lib/media/focus.ts` | `MEMO` | pure crop memo keyed by the crop's own inputs (no store data) |
   | `src/lib/sheets/client.ts` | `__codSheetsToken` | the platform service account's access token (one platform account) |
   | `src/lib/sheets/sync.ts` | `__codSheetsHeaders` | header columns per spreadsheet and tab (a spreadsheet belongs to one store after the proof, SHT-09) |
   | `src/lib/sheets/sync.ts` | `__codSheetsSync` | the coalescing push state per store id (SHT-04) |

   The remaining `new Set(` / `new Map(` at module scope in T4's files are immutable lookup constants (for example
   `src/lib/media/sniff.ts` `AVIF_BRANDS`, `src/lib/media/video.ts` `KEEP_TOP`, `src/lib/sheets/orders-sheet.ts`
   `LABEL_TO_STATUS`, `src/lib/sheets/format.ts` `GOOGLE_HOSTS`, `src/lib/editor/paths.ts` `BANNED`,
   `src/lib/editor/actions.ts` `GATE_CODES`, `src/lib/orders/conversions-core.ts` the Meta / TikTok error-code sets).
   Either the lint skips a `const` initialised with literal members and never mutated, or each needs an entry with the
   reason "constant".

2. L12 ("a "use server" file that handles publish without calling `runPrePublishChecks()`"):
   `src/app/app/[store]/pages/actions.ts` and `src/lib/editor/actions.ts` publish only through T3's scoped
   `publishPage(scope, …)`, which awaits `runPrePublishChecks(ctx)` before it writes the version row (§M.1 step 1).
   If the lint matches the call literally in the action file, it should accept a call of the scoped `publishPage(` as
   the gate (or the allow file names the two files with that reason). Calling the checks a second time in the actions
   would run every gate twice and could disagree with the publisher's own run.

its files against the rule texts by hand at its last step (L7, L8, L9 and L13 are now clean in T4's files, see
`docs/saas/ccr/r1.0-t4-report.md`); L4 and L12 cannot be cleared without the allow file.
