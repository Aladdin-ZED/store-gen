## What

1. **Base catalogs (maintainer).** T2's surfaces (`/login`, `/signup`, `/invite`, `/reset`, the store picker, `/app/new`,
   `/app/account/**`, `/app/<h>/team`, the console's R1.0 screens) render through the admin i18n skeleton with the
   identity catalog `src/lib/auth/i18n/{en,fr,ar}.ts` (476 keys in en, every tenant key in fr and ar; `console.*`
   English only). Its lookup (`src/lib/auth/i18n/index.ts`) reads the base catalogs **first**, so spreading the three
   files into `src/lib/i18n/admin/{en,fr,ar}.ts` changes nothing on screen:

   ```ts
   // src/lib/i18n/admin/en.ts
   import { messages as identity } from "@/lib/auth/i18n/en";
   export const messages = { ...identity, "error.invalid": "…", /* core keys */ } as const satisfies Record<string, string>;
   ```

   This supersedes the key tables of CCR r1.0-t2-5 (same keys, same values, now in files). At P0 the keys move without
   renames to P2's `<locale>/{auth,team,onboarding,shell}.ts` and P1's `<locale>/{console,notify}.ts`, and
   `src/lib/auth/i18n/index.ts` becomes a thin re-export of `t`.

2. **`/admin` resolves twice (maintainer, T4).** §I.2 gives T2 `src/app/admin/page.tsx` (the console's R1.0 home: who
   is signed in, step-up freshness, the session's own view-as with End, the PLA-§10.1 start sheet). Today's dashboard
   `src/app/admin/(panel)/page.tsx` (T4) resolves to the same URL; `tsc` can't see it, but `next build` and `next dev`
   refuse two pages for one path. T4 moves that dashboard to `/app/<h>` in R1.0, so: merge T2's `admin/page.tsx`
   **with or after** T4's move, or delete `(panel)/page.tsx` in the T2 merge commit. Until then the owner's dev server
   on main must not get both files.

3. **Auth pages: Arabic face, nonce, CSP (T3).**
   - `src/app/layout.tsx`: load IBM Plex Sans Arabic (DS21, already in devDependencies as
     `@fontsource/ibm-plex-sans-arabic`) as `--font-arabic`, and give `[lang="ar"]` the stack
     `var(--font-arabic), var(--font-sans)`. The identity shells set `lang` / `dir` on their own root element (the
     root `<html lang="en">` is shared), so the rule must match a descendant, not only `html`.
   - The `auth` and `app` areas need the platform nonce (`x-nonce`) like `/admin`: `AdminProviders` passes it to the
     theme script and the Turnstile field sets it on the widget's script.
   - Their CSP must allow the platform widget: `script-src https://challenges.cloudflare.com` and
     `frame-src https://challenges.cloudflare.com` (rendered on `/login` after 3 failures, on `/signup`, `/invite/*`
     and `/reset/*` whenever `platform_turnstile` is configured).

4. **Notification kinds (maintainer, P0 registry; P1 owns them).** T2 calls `notify()` with these kinds; the texts
   `notify.<kind>.title` / `.body` are in the identity catalog (ar / fr / en):

   | Kind | Audience | Vars | Link |
   |---|---|---|---|
   | `invite.accepted` | user (the inviter), store | `{ member, role }` | `/app/<h>/team` |
   | `member.role_changed` | user (the member), store | `{ role }` | `/app/<h>` |
   | `member.suspended` | user (the member), store | `{}` | none |
   | `store.impersonation_started` · `store.impersonation_ended` | store_role owner, admin | `{ reason, from, to }` (ISO) | `/app/<h>/settings/audit` |
   | `staff.impersonation_started` | platform_staff, minRole admin | `{ store, by, minutes }` | `/admin/stores/<id>/activity` |

   PLA-§18.2 writes `invite.accepted` / `member.joined` vars as `{ name, role }`, but `test:platform` refuses a vars key
   named `name`; T2 sends `member` (a display name ≤ 60 characters). `notify()` itself drops keys named phone, name,
   address, email and note before the insert.

5. **c0a-smoke (maintainer).** `scripts/qa/c0a-smoke.ts` expects "signed out → 307 to `/admin/login`" for `/app/<h>`.
   The seam now sends a signed-out visitor to `/login?next=/app/<h>` (§B.1: the one sign-in), and the old console URLs
   `/admin/login` and `/admin/login/verify` only redirect there behind the gate. Change the expected `Location` to
   `/login?next=%2Fapp%2F<h>`.

6. **Legacy /admin pages (T4).** Until the integration deletes them:
   - `SecurityPanel` and `TeamPanel` keep their legacy exports and props (the account page uses

7. **Seat gauges (T1).** `createInvite` and `acceptInvite` call `assertWithin(scope, { metric: "members", period:
   "total" }, 1)` (and `agents` for an agent invite) inside the transaction that locks the store's member rows. The
   gauge must read the live membership count (or be charged by the membership insert): a gauge that nothing charges
   would never refuse. Until T1 merges the stub is read as "no limit" (logged once).

8. **Tenancy lint (C0b).** Two platform writers take a store id that is not a scope parameter, by design:
   `src/lib/platform/notify.ts` (the frozen `NotifyTarget` carries `storeId`) and `src/lib/platform/impersonation.ts`
   (the view-as rows are platform bookkeeping). Both write through `systemScope(systemCtx("notify" | "impersonation"),
   storeId)` + `storeValues` / `whereStore`, never a raw `store_id`; if L2's provenance rule flags them, allow-list
   these two files with that reason.

## Why

(1) D65 / §I.5: the R1 surfaces must be complete in ar / fr / en, and T2 owns no catalog file. (2) A build that fails
on a route clash blocks the R1.0 gate. (3) Without the face, Arabic falls back per glyph; without the nonce and the
CSP origins, the human check never renders and approval / open sign-ups are refused. (4) Kinds without a registry
entry render as raw keys in P1's centre. (5)-(8) keep the existing checks honest after this step.

## Effect on others

No frozen contract changes (PageDoc v2, runtime config v2, payload v2, PHP export, the landing chunk untouched;
`npm test` and `test:php` green). (2) is a merge-order constraint only.
