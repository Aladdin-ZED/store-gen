# r1.0-t3-2: the in-app gate re-check uses the effective host class, like the proxy

- Status: open
- Filed by: T3 · Owner of the file: T2
- Files: `src/lib/auth/gate.ts`

## What

1. `isAdminHost(headers)` (and so `hasGateAccess`, `hasAdminAccess`, `assertAdminAccess`) decides on the §C.2
   effective host class rather than the raw `requestHost()`:

   ```diff
   +import { effectiveHost } from "@/lib/edge/host";
   …
    /** ADMIN_HOST check: true on the dedicated admin host, or anywhere when none is configured. */
    export function isAdminHost(headers: Headers): boolean {
   -  const dedicated = adminHost();
   -  return dedicated === null || requestHost(headers) === dedicated;
   +  const cls = effectiveHost(headers).cls;
   +  return adminHost() === null ? cls === "platform" : cls === "console";
    }
   ```

   The doc comment becomes: "true on the console host (ADMIN_HOST), or on the platform host while no ADMIN_HOST is
   set; never on a store, custom, legacy, reserved, invalid or foreign host".

2. `adminAreaOf()` has no caller left: `src/proxy.ts` now uses `areaOf()` from `src/lib/edge/areas.ts`, which keeps
   the same decoding and case folding. Delete it when convenient.

## Why

§C.3: "Today's gate logic for `gate`, `console`, `console-api` (…) **evaluated on the effective host**". The proxy
now refuses the console on every class except `platform` (shared origin) and `console` (ADMIN_HOST). Today's
re-check answers true on **every** host while ADMIN_HOST is unset: a store subdomain through the Worker, a legacy
host and a foreign host. It is the defence in depth behind the proxy (`assertAdminAccess` on every admin page and
action), so it should not be wider than the outer wall. A Server Action is a POST to a page route. If the proxy
matcher ever stopped covering a console path, the re-check would be the only gate.

`effectiveHost()` already treats a present-but-unverifiable `x-sg-edge` as `invalid` (SEC-4) and trusts `x-sg-host`
only when the edge key and timestamp verify. Development keeps working: local hosts are `platform` outside
production.

## Effect on others

- The gate cookie's fingerprint (`fingerprint()`) is unchanged, so every issued gate cookie stays valid.
- `test:hosts` (`src/lib/edge/selftest.ts`, section 6) already asserts the console-host and shared-origin cases. T3
  adds the store-host and legacy-host refusals once this is applied.
- None for the frozen contracts.
