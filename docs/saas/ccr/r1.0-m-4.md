# r1.0-m-4: `src/lib/media/store.ts` raw SQL without a store predicate (lint L10 ×3)

- Status: forwarded to the maintainer at the R1.0 integration, after the T4 merge (filed in 54de35c)
- Filed by: maintainer (C0b merge, lint baseline "after T1 + T2") · Owner of the file: none in R1.0 (T4 owns
  `src/lib/media/**` except `store.ts`; P8 takes `store.ts` in R1 product)
- Files: src/lib/media/store.ts (`insertFiles`, `deleteFilesOfAsset`)

## What

`INSERT INTO media_files (...)`, `SELECT ... FROM media_files WHERE asset_id = ?` and `DELETE FROM media_files WHERE
key IN (?)` name no `store_id`. The fix needs the store of the asset, which only T4's media callers (`assets.ts`,
`process.ts`) will hold as a `WriteScope`:

- `insertFiles(conn, scope: WriteScope, assetId, files)`: the INSERT names `store_id` with `scope.storeId`;
- `deleteFilesOfAsset(conn, scope: WriteScope, assetId)`: both statements add `store_id = ?`.

`media_chunks` has no `store_id` (keyed by the media key) and is not a tenant table.

## Why

R1.0 exits with 0 lint violations (§K.1, §J.5). Changing the signatures now would collide with T4's rewrite of the
callers in its worktree, so the maintainer applies it right after the T4 merge, in the same step that removes the
deprecated `string` overloads of `rateLimit` / `rateLimitReached`.

## Effect on others

T4: none while it builds (its callers keep today's signature); at the T4 merge the maintainer passes the callers'
scope through.

## Update (C0b review fixes)

L10 now reads SQL wherever it goes, so a fourth statement of `store.ts` is reported: the media-key lookup
``SELECT … FROM media_files WHERE `key` = ? LIMIT 1`` (line 266, run through the local `mediaQuery` helper). A media key is
global and random, so this one is a public-key lookup (§E.3 rule 6): at the R1.0 integration it either moves behind
`src/lib/tenancy/public.ts` with `// tenancy: public-key media`, or takes the store predicate with the other three.
