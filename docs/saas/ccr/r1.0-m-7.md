# r1.0-m-7: the landing chunk's byte-saving refactors are accepted with the storage prefix (§C.9, header freeze rule)

- Status: applied in the commit "R1.0: T3 EDGE (…) review fixes": §C.9 and the header freeze rule say so; the runtime
  selftest pins the behaviour.
- Filed by: maintainer (R1.0 review of T3, finding 8) · Owner of the file: maintainer (`src/landing/runtime/landing.sha256`,
  `budgets.json.landing`); the spec owner for the wording
- Files: docs/STORE-SAAS.md header freeze rule and §C.9; src/landing/runtime/selftest.ts

## What

1. Record that the R1.0 integration accepted, beside the storage prefix, these **behaviour-equivalent** edits of the
   frozen chunk that T3 made to win back the prefix's bytes (commit de7adbd), all covered by the `landing.sha256` pin:
   - `core.ts` `flag()`: one comparison `on !== el.hasAttribute(name)` instead of two branches (same DOM writes: none
     when the attribute already matches);
   - `core.ts` `disable()`: `String(off)` instead of `off ? "true" : "false"`;
   - `tracking.ts`: `PARAMS` loses its payload-key column (the key is the parameter without `utm_`, lower-cased, so
     `ScCid` is `sccid` as before), one `collect()` helper reads the URL and the session restore, `adIds()` loops over
     `fbp` / `fbc` / `ttp` with the same limits and the same `fbc` rebuilt from `fbclid`.
   - the prefix is computed by `skey(win, key)` on each storage access from `location.pathname` rather than once at
     init: the same regex over the same path gives the same name for the life of the page (the runtime never changes
     `location.pathname`), so "derived once" holds as "derived in one place".
2. §C.9 and the header freeze rule name them, so a later reader comparing the chunk with its baseline finds them
   sanctioned rather than silently covered by the new sha.
3. `src/landing/runtime/selftest.ts` (npm test) carries parity cases against the baseline implementations (copied from
   776d24c): `captureUtm` from the URL (both cases of `ScCid`, trimming, the length limits, the session copy written)
   and from the session restore, `adIds` with and without cookies (`fbc` rebuilt from `fbclid`), `flag` / `disable`
   (attribute writes), and `skey` per path.

## Why

Reverting them would put back about the bytes the prefix cost and force a re-freeze of the chunk size; payload v2 keys
and every observable behaviour are unchanged, which the parity cases now prove instead of a reading of the diff.

## Effect on others

None: payload v2, runtime config v2 and the markup contract are unchanged; `landing.sha256` and `budgets.json.landing`
stay as recorded at the T3 merge.
