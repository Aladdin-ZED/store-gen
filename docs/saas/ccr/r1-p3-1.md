# r1-p3-1: export the guard's number rule (`allowedNumbers`, `numbersIn`) from `src/lib/ai/guard.ts`

- Status: open (filed at P3 wave 1, step p3-w1-policies-honesty). Nothing breaks while it is open: P3 runs a
  line-for-line adapter and checks it against the guard's exported entry point.
- Filed by: P3 LANDING · Owner of the file: P7 AI (applied by P7 in its own tree, or by the maintainer at the P7 merge)
- Files: `src/lib/ai/guard.ts` (P7); then `src/lib/landing/honesty/guard-numbers.ts` (P3, the adapter becomes a
  re-export)

## What

1. `src/lib/ai/guard.ts`: export the two private helpers unchanged (no body change, no rename):

   ```diff
   -function numbersIn(s: string): string[] {
   +/** The numerals of a text, Latin and Arabic-Indic digits, "," read as "." (exported for the honesty gate, LAN-§6.4 rule 5). */
   +export function numbersIn(s: string): string[] {
      return ASCII_DIGITS(s).match(/\d+(?:[.,]\d+)?/g)?.map((n) => n.replace(",", ".")) ?? [];
    }

    /** Numbers the copy may mention: those the merchant gave us (facts, name, price, delivery line). */
   -function allowedNumbers(ctx: GuardContext): Set<string> {
   +export function allowedNumbers(ctx: GuardContext): Set<string> {
   ```

2. After (1) lands, P3 replaces the body of `src/lib/landing/honesty/guard-numbers.ts` with:

   ```ts
   export { allowedNumbers as guardAllowedNumbers, numbersIn as guardNumbersIn } from "@/lib/ai/guard";
   ```

   (P3's own file; no CCR needed for this half.)

## Why

landing.md LAN-§6.4 rule 5: "the gate reuses the guard's number rule rather than re-implementing it:
`allowedNumbersFor` wraps `allowedNumbers(ctx)` and adds the pricing, zone, policy and countdown classes". The rule
lives at `src/lib/ai/guard.ts:47-67` and is not exported, so the gate cannot import it.

Until this is applied, `guard-numbers.ts` holds a line-for-line copy of the two functions, and `test:honesty` (section
2) checks the copy against `cleanAiText`, the guard's exported entry point: a generated line made only of numerals the
adapter allows passes `cleanAiText`, and a line with one numeral the adapter refuses is rejected by it. If P7 changes
the rule before exporting it, that check fails in P3's suite at the next merge, so the two can never drift silently.

## Effect

- No behaviour change in P7: two `export` keywords.
- The honesty gate and the AI guard read numerals through one function, as rule 5 requires.
- `src/lib/contracts/r1-p0.ts` needs no change (neither name is frozen).
