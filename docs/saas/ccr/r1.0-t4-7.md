# r1.0-t4-7: the proxy matcher leaves out the store media upload endpoint

- Status: applied by T3 in 9013726: the §C.3 matcher already leaves out `api/app/[^/]+/media$` (src/proxy.ts); no
  change at the merge.
- Filed by: T4 · Owner of the file: T3
- Files: src/proxy.ts

## What

The matcher of §C.3 (`docs/STORE-SAAS.md`, "Matcher (constants only)"), which T3's host-class proxy carries:

```diff
-    "/((?!_next/static|_next/image|favicon\\.ico|fonts/|media/|api/admin/media$).*)",
+    "/((?!_next/static|_next/image|favicon\\.ico|fonts/|media/|api/admin/media$|api/app/[^/]+/media$).*)",
```

and the comment above it names `/api/app/<handle>/media` next to `/api/admin/media`.

## Why

MED-16. T4 moved the media API to `src/app/api/app/[store]/media/**` (§I.1, §G.4; `src/app/api/admin/media/**`
is gone). The proxy clones every matched non-GET body into memory up to `experimental.proxyClientMaxBodySize`
("1mb", `next.config.ts:18`) and, past it, hands the route **only the first megabyte** (the Next 16 docs:
`node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/proxyClientMaxBodySize.md`,
"Behavior"). Until the upload endpoint is outside the matcher, every upload above 1 MB reaches the route truncated
and answers 400 "The upload was interrupted". The route needs nothing from the proxy: it calls `storeGuard`
(session, membership, `effectiveHost()` class `platform`, same-origin) itself before reading the body.

`/api/app/<handle>/media/<id>` (the framing data, small JSON bodies) stays inside the matcher: the `$` anchors the
exclusion to the upload path only.

## Effect on others

- None on frozen contracts.
- `src/lib/auth/host-selftest.ts` (T3) can add `/api/app/<h>/media` to its "outside the matcher" cases.
