## Why

`src/lib/render/selftest-public.ts` is T3's DB-backed proof of the R1.0 step "public-routes-render" (§C.1, §C.4.1,
§C.8, §E.2, §E.5, §H.13, D54, STAT-01 … 04, SEC-7). It creates, migrates and drops its own `cod_test_t3_public`
database on XAMPP, so it belongs to `test:db` (§J.2), not to `npm test`.

It runs with plain `tsx`, not `--conditions=react-server`: it renders store documents, and under that condition
`react-dom/server` resolves to its throwing RSC build. The suite maps `server-only` to its empty build itself
(a `Module._resolveFilename` hook in the file), the way Next's route layer does.

Until T1 merges, its 4 checks that read T1's settings API or envelope (`getStoreSettings`, `seal` / `open`) report
"deferred (T1 stub)" and the suite still exits 0. After T1 merges they run in full; the R1.0 integration should see
`ALL OK (0 deferred …)`.

## Effect on others
