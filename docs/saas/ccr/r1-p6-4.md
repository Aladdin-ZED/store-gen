- Filed by: P6 · Owner of the file: maintainer (core §K.3; `src/lib/render/selftest-prepublish.ts`)
- Files: `src/lib/render/selftest-prepublish.ts` (one check), no code of another track
- Relates to: r1-p0b-report.md P6-9 (deferred to the P6 merge: "`test:prepublish` enables the C2, C3, F1 hard
  fixtures and the DES-§25.1 design cases")

P6 step 3 replaced the P0 stubs `estimateHeights` and `variantFeatures` (`HEIGHT_MODEL_VERSION` = 1; every report
without `stub`; every variant declares its `features`, glass included). From that commit on, one check of
`test:prepublish` fails in P6's worktree, so `npm test` stops there. Every other check of the file passes, the lock
proof of `--slow` included.

## What fails, and why it is the check's premise, not the model

The check "rows without heights: F5 weight, R1 order buttons, R5 reveals, K2 colour bands, I1 photo reuse classify
hard past the limit, soft past the note line" starts from

```ts
// a document whose own sections trip no row: every background neutral
const clean = { ...doc, sections: doc.sections.map((s) => ({ ...s, bg: "base" as const })) };
assert.deepEqual(hardIds(budget.budgetReport({ doc: clean })), []);
```

`doc` is the argan baseline fixture: 27 sections, about 30,000 px at 390, the form on screen 14 or so, five glass
surfaces outside nav and sticky. Under the stub every section was 600 px and every variant had `glass: 0`, so the
fixture tripped no row. With the real model it trips exactly what §M.2 exists to refuse:

```
+ [ 'budget:C3', 'budget:C3', 'budget:F1', 'budget:C2', 'budget:C2', 'budget:R4' ]
- []
```

These rows are correct:
- C3: 27 sections > 16, and about 30,300 px > 15,000.
- F1: the form top is past 3,000 px.
- C2: the COD line and the CTA are estimated past 938 px. The measured renders agree: `calibration/heights.json`
  has the argan fr COD line at 1,050 px.
- R4: more than 4 glass surfaces.

The check is about the five rows that need no height. Its "clean" document is clean only for those five rows.

The rest of the check does not change. Its last assertion, `budgetResult({ doc: bands })` refused with `budget:K2`
among the items once the model is real, already holds.

**Verified.** A copy of the file with only this diff applied (`qa/p6/prepublish-patched.ts`, git-ignored, imports
re-pointed to `@/`) passes all 13 checks on P6's tree with `--slow` (2026-10-29). That includes the child-process
lock proof: `stub-lock.ts` exits 0 without `SG_STUB_BUILD_OK`, and `budget.ts` loads under `NODE_ENV=production`.

## Why

`npm test` must stay green from the P6 merge on (core §J.1). P6 cannot edit the file. The alternative, a model that
under-reports the baseline fixture, would be dishonest, and the gate would stop refusing the pages it was written
against.

## Effect on others

None. The check gets narrower. The C2, C3 and F1 hard fixtures of P6-9 (`calibration/heights.json`) are still the
maintainer's to add at the P6 merge. Until this CCR is applied, `npm test` in P6's worktree stops at this one check.
P6's step reports run the suites after it one by one.

## Addendum (P6 step 8): the fixture builders for the design cases

The design cases of P6-9 / DES-§25.1 can now import their pages from `src/lib/design/fixtures/prepublish.ts`
(test-only, pure, deterministic): `cleanDoc(name, locale)` is a generated direction after the wizard repair (0 design
hard items, the passing side of every TC-1 pair), `baselineDoc(name, locale)` the fixture default without a look (the
27-section baseline-like page), `slopDoc()` the ghost / ring / three-glass / two-strips / numbered-eyebrow page, `mutate`
a sandbox copy with one change, `gateInputOf(doc)` the landing `GateInput`, and `storeTemplate(kind, locale)` a
`defaultTemplate`-style store document per kind. `test:design` (the `tc1`, `calibration` and `kinds` groups) gates the
same pages, so both suites read one set of fixtures.
