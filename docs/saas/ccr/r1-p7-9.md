# r1-p7-9: `ai_jobs.input`, the stage input of a detached job

- Status: deferred to the integration: a schema + 0005 snapshot change; the job input and reservation work today inside `result` as internal JobDoc keys.
- Filed by: P7 (step 8) · Owners: maintainer (src/lib/db/schema.ts, drizzle/0005_r1.sql, drizzle/meta/0005_snapshot.json)
- Files after the change: src/lib/ai/store/jobs.ts, src/lib/ai/jobs/{enqueue,claim,run}.ts (P7)

## What

Pattern B jobs are stage-resumable across requests and drivers (AI-§B.13 step 3): a poll, `after()` or a one-item
batch may run the next stage in another process, so the job's input must live in the row. `ai_jobs` (0005) has
`input_hash` but no input column, and AI-§M.1 does not name one.

Until this CCR lands, step 8 keeps the redacted job input (and the plan and the job's one reservation) inside the
`result` LONGTEXT as internal keys of `JobDoc` (src/lib/ai/store/jobs.ts): the view strips every internal key, and the
input is dropped in the terminal write. The frozen public shape of `result` (`{ runIds, outputRef?, instant?,
critique? }`) is unchanged for every reader.

Proposed (0005 is not deployed, like P0b's CCR P7-3):

```ts
// src/lib/db/schema.ts, aiJobs, after `inputHash`
/** the redacted job input (stage inputs by stage base), ≤ 1 MB; NULL from the terminal write on (AI-§B.13) */
input: jsonText<unknown>("input"),
/** the job's one reservation of every stage (AI-§C.2), reconciled at the end */
reservation: jsonText<ReservationJson>("reservation"),
```

`drizzle/0005_r1.sql`: `ALTER TABLE ai_jobs ADD COLUMN IF NOT EXISTS input LONGTEXT NULL AFTER input_hash, ADD COLUMN IF
NOT EXISTS reservation LONGTEXT NULL AFTER input;` (guarded like the other 0005 statements) and the snapshot.

At the merge P7 moves `JobDoc.input` / `JobDoc.reservation` to the columns (one change in ../store/jobs.ts `insertJob`,
`docOf` and the drivers' reads); `result` then holds only its documented keys plus `outputs` and `plan`.

## Why

A stage must find its input whichever driver runs it, and the reservation must outlive the creating request to be
reconciled when the last stage ends, on cancel, on failure or by `ai.reconcile` (AI-§C.2 step 6). Keeping them inside
`result` works but blurs the column's documented shape and its ≤ 64 KB rule (an input with photos is larger).
