## What

1. `src/lib/orders/log.ts`: `logError` also counts the failure. `errors.ts` imports `errorSummary` from this file, so
   the import is lazy. That keeps the module graph acyclic, and `log.ts` stays importable from files without
   `server-only`: it has no server-only marker, and `recordError` loads only on the server path that logs.

```diff
 /** Log an unexpected failure without request data (no PII in logs). */
 export function logError(scope: string, err: unknown): void {
   console.error(`[${scope}]`, errorSummary(err));
+  // the error ring (§H.5): area = the scope before ':' ("orders:create" → "orders"); never throws, never waits
+  void import("@/lib/jobs/errors").then((m) => m.recordError(scope.split(":")[0] ?? scope, err), () => undefined);
 }
```

## Why

§H.5: `logError` and the action wrappers feed the error ring. `getHealth().errors` and `edge.badKey24h` /
`prevKeyRequests24h` read `error_events`, which seam.ts and host.ts already document as arriving with 0005.

## Effect on others

None on frozen contracts: `actionFailure` gains an optional third argument, and `logError`'s signature is unchanged. No
customer value reaches a row: the sample is `errorSummary(err)` with e-mails and digit runs masked (the test:jobs
canary cases).
